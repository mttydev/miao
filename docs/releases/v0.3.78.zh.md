# miao v0.3.78

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.78.md)

v0.3.78 堵上了暂停中的会话仍可能整轮失败的最后一条路径；在 agent 改动文件前保留一份可回退的检查点；为会话提供持久的 workspace 记忆并注入上下文；把 Session 对话框变成一屏即可看清各会话正在做什么的实时视图。

## 暂停不再让整轮失败（#3083）

同一个未变动的待办列表连续触发了两次暂停，后台 job 从两个减到一个。暂停通知的持久 id 只由列表签名和轮次推导，而 `waiting` 暂停的轮次恒为 0，正文却写着还有几个 job 在跑。于是第二次暂停变成「同一 id、不同文本」，存储层按冲突拒绝，整轮在通知写入前就以 `input id conflicts with an existing admission` 失败。

现在通知正文参与身份构造；引擎自身的 `loop-blocked` 与 `loop-armed` 状态写入同样处理，因为它们的载荷包含会变化的停滞计数，以及解除阻塞的来源。完全相同的重复仍会去重，内容变化则记为新的事实。

## 编辑保留检查点（#3085）

在 `write_file` 或 `edit_file` 改动文件之前，当前内容会保存到 workspace 内的 `.miao/checkpoints/`，改错后可以回退到改动前的样子。检查点按文件保留，每个文件上限 5 份，超出时淘汰最旧的一份；文件尚不存在时不会生成检查点，因为首次写入之前没有可回退的内容。

## 会话记住 workspace 事实（#3084）

agent 在压缩与重启后会忘记 workspace 中的事实。会话现在可以把它们持久化到 `.miao/memory.json`：条目初始为「未审核」，引擎以 `<memory>` 块注入系统上下文，并标注未审核条目。存储损坏时静默降级为空——记忆只是辅助信息，绝不阻塞会话。

## Session 对话框成为实时 agent 视图（#3082）

对话框过去只列身份信息，想观察后台工作就得逐个打开会话。现在明细行汇总了实时状态：运行中的会话带一个圆点，显示既未完成也未取消的待办数量，以及 goal 是否仍处于武装状态。键名保持原样，增量采样与合并行为不受影响；只要还在渲染帧，对话框最多每两秒重新查询一次目录。
