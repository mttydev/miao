# miao v0.4.9

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.9.md)

v0.4.9 修复了自动上下文压缩会永久停摆的问题，恢复了 Command Code 的模型列表与按套餐路由，让中文输入框提示重新可读，并让会话在等待或压缩时显示自己正在做什么。

## 自动压缩不再永久停摆

会话可以停在上下文窗口的 97%、自动压缩处于开启状态却再也不收缩。问题不在触发：压缩确实在 655,360 窗口的 640,450 tokens 处启动，摘要模型也成功返回。随后提交以 `unmatched tool result` 拒绝了检查点——而且每次都会。

原因是一个中断的回合把同一个回答写了两次：停止路径为尚未执行的工具调用补写「the turn stopped before it ran」，运行结算又为仍处于 planned 的同一调用补写「Execution stopped before dispatch」。第二条成了无主结果，而压缩切分对前缀做严格校验，于是这个前缀永远无法被切分。

现在运行结算在为调用合成回答前先检查是否已有回答；前缀校验允许「已结算调用的重复回答」，但仍拒绝从未存在过的调用所产生的回答。后半部分不只防新问题：已经被已发布版本写坏的历史，升级后无需改数据库就能重新压缩。

## Command Code 的模型列表回来了

Command Code 的模型列表既不带能力也不带价格，目录因此对大多数条目省略了 `modalities`。路由派生把“缺失”读成了“不产生文本”，最终只有那个碰巧声明了文本输出的免费模型活了下来，连上 key 后看起来只有一个模型。

现在缺失的能力声明按“未知”处理，而不是按“不可用”处理；目录里标记为 `deprecated` 的条目也会跳过，与产品既有的 `enabled` 规则一致。同一处修正还让 Command Code 指向 Provider API 的 `/provider/v1`，其 Claude 模型改走 `/messages` 与 Anthropic 协议，其余模型仍走 `/chat/completions`。

## 套餐决定模型列表

Command Code 按订阅档位限制模型。`providers.commandcode.plan` 可写 `go`、`goat`、`pro` 或 `max`；Max 10× 与 Max 20× 都映射到 `max`。同一个 provider 存放了不同套餐的 key 时，可用 `account_plans` 按账户标签分别指定：

```jsonc
{
  "providers": {
    "commandcode": {
      "plan": "pro",
      "account_plans": { "work": "max" }
    }
  }
}
```

目录条目没有列出档位、或列出了账号所在档位时，该模型可选。无法识别的套餐（如 `team`、`provider`）不隐藏模型；不写套餐则保持原有行为。只写套餐的 provider 配置会与目录合并，而不是覆盖目录，所以不会再出现“一写 plan 所有模型都不见了”的情况。

Go 套餐不含 Provider API access，第三方客户端需要 GOAT 或更高档位。这是 Command Code 的限制；选择器仍按目录显示，因为账号之后可能升级。

本次也对照官网重新核对了 OpenCode：按量付费 Console（`opencode`）与 Go 订阅（`opencode-go`）继续是两个独立 provider；Go、Go Plus、Go Teams 三档覆盖同一组模型，因此 `opencode-go` 不按套餐过滤，套餐改变的是额度而不是可选模型。

## 输入框提示重新可读

空输入框的中文提示被切掉了半个字：`随便问…` 显示成 `便问…`，因为终端块状光标占据输入框首格，而一个汉字占两格。现在提示文字从光标右侧一格开始：光标独占一格，首个汉字完整可见，实际输入的草稿仍从第一列开始。

## 等待中的回合会说明自己在做什么

- 会话等待的作业会显示实时进度——作业名、已用时间与预计时间——而不是一行冻结的 `working`。
- 压缩过程显示为实时的 `compacting context` 段，带已计数与总 tokens；提交后转录中仍保留自己的记录。
- 纯等待不再向转录注入 `Task paused` 提示；等待状态本身即是提示。需要决策的暂停（回合预算、花费、停滞）保留说明。
- 被停止的回合会记录停止原因与发起方，之后再读转录会显示 `interrupted`，而不是看起来像回答被截断。
- 宿主底栏的每条事实可以携带可选的 tone；早于该字段的宿主会沿用自己的文字颜色。

## 兼容性

没有协议或存储变更。`plan` 与 `account_plans` 是可选 provider 字段，既有配置的模型列表保持不变。Command Code 的非 Claude 路由现在指向 `/provider/v1/chat/completions`，Claude 路由使用 `/provider/v1/messages`。底栏 tone 是既有底栏 wire 上的可选字段。已经因重复结果历史而无法压缩的会话，升级后会在下一个稳定回合恢复。

## 维护与验证

`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、TUI 全量套件（780 条）、引擎 `store`（24 条）与 `history`（10 条）套件、12 个 `native_routes` 测试以及完整 `miao-engine` 库测试（593 项）在 Rust 1.100 stable 上通过。压缩修复带有两条在旧代码上会失败的回归测试；输入框测试断言绘制出的提示恰好位于上报光标右侧一格；路由测试覆盖没有 `modalities` 的目录条目、`deprecated` 条目、Command Code 的两种线路，以及按账号过滤套餐。
