# miao v0.3.99

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.99.md)

v0.3.99 让模型编造的「上下文窗口用完」借口无法再停住会话：引擎会用自己实测的占用数据当场纠正并继续工作。

## 编造出来的「上下文用完」

弱模型经常在自治任务途中宣布上下文窗口已满、建议用户开新会话，而侧栏显示的占用远低于压缩触发线——一个长建图会话在 868.9k 窗口只用到 61% 时就宣称「用完了」。自动压缩从来不是问题：该会话早已压缩过一次，触发线在窗口填满之前就会生效，引擎也不存在任何「必须开新会话」的机制。停机是模型自己编的理由；由于循环的 text-only 暂停不携带任何反驳信息，这套说辞带着三条编造的「原理」直达了操作者。

现在，排水循环会把 text-only 回复与引擎实测占用对照。当回复声称窗口耗尽（保守的双语匹配：窗口词 + 耗尽词，或明确让用户开新会话）而实测计数仍低于压缩阈值时，循环会注入一条携带实测数据的纠正并继续——「context window carries X of Y tokens (Z%), against a compaction threshold of T」——并要求模型用工具继续干活、不得转交新会话（#3229）。每个 prompt 的纠正上限 2 次；越过上限后仍谎报的，暂停消息会带上同样的实测数字，让借口与反驳它的数字同时到达，`/compact` 仍是手动压缩入口。没有实测占用、或占用已越过阈值时，行为不变，仍由原有压缩门接管。
