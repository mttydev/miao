# miao v0.4.8

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.8.md)

v0.4.8 补完侧栏的语言切换，补齐命令与 Provider 配置方面缺失的文档，并修复了 Goal 花完额度后可能卡住会话的预算闸门。

## 侧栏跟随所选语言

目标面板、计划/配额块、会话用量账本、活动计数和子代理行此前仍是英文，而 TUI 其余部分已跟随 `/lang` 选择。现在它们都从词表读取：`GOAL` / `PLAN · QUOTA` / `SUBAGENTS` 标题、目标与计划状态、步骤、预算、文件计数、配额重置倒计时、`no usage yet`、重试/尝试/返工计数，以及手动审批的底栏事实（`ask approval` / `逐次批准`）。

颜色改为按词表 key 选择，而不是按英文字符串匹配，所以中文界面保留与原文一致的警告色与强调色。

## 文档：FAQ 与命令参考

新增的 FAQ 页面回答了反复出现的问题——会话与恢复、上下文与压缩、权限与审批、Provider 密钥与路由；命令参考则在一处列出所有命令与快捷键。指南与 Provider 页面做了精简，改为指向这些页面而不是重复内容。

## 新消息会重开 Goal 的预算窗口

Goal 从记录它的那次修订开始计算轮次，而预算闸门此前每轮只读取一次声明。第一段工作花完额度后，之后每条消息都会在第一个模型轮次之前被拦下，继续输入也无法推进；中途声明的 Goal 更是完全未被约束。现在闸门在每个模型轮次边界刷新，提交人类输入时按 `max(promotion, goal revision)` 重开 Goal 窗口。配置里的会话级预算仍然有效，仅排队（queue）的输入仍会等待。

## token 预算属于运维方

模型无法估算 token：促成这次修复的事故里，模型为 300 轮的 Goal 声明了 300 万 token，最终花了 1.36 亿。`budget.max_goal_tokens`（默认 20,000,000，在读取时生效，既有配置无需改写）现在会封顶 Goal 可声明的任何 token 数字。超过上限的声明会被拒绝，并提示先以可观测单位（时间或下一个检查点）询问一次额度，然后改写为轮次或墙钟时间。

## 兼容性

无协议或存储变更。`budget.max_goal_tokens` 是可选键，缺省按 20,000,000 读取，既有配置照常工作。耗尽的 Goal 预算不再否决你的下一条消息；配置里的会话级预算不变。

## 维护与验证

`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、全量 TUI 测试（770 项）与引擎预算相关测试（`cost_budget`、`config_derive`、`permission`）在 Rust 1.100 stable 上通过，包含中英文两种界面下的侧栏目标区测试。
