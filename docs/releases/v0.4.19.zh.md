# miao v0.4.19

v0.4.19 修复了「作业早已结束、状态行却还挂着」的问题，另外带上它旁边两处较小的缺陷。

## 结束的作业不再被画成运行中

一个会话可能一直停在 `等待 1 个后台作业 · 已运行 2h 3m`，而它启动过的每个作业都已是终态——引擎自己的作业表里只有 `completed`、`failed`、`cancelled` 和 `unknown`。

这行背后的规则本身是对的：只有缓存行仍处于非终态时才显示，且所有缓存行都到终态时时钟停止。缺陷出在更前面一步——刷新这些行的读请求把自己的失败吞掉了：

```rust
if let Ok(value) = client.request("jobs", …).await {
    …                                  // 失败时：什么都不发
}
```

于是一次读失败之后，上一次的行原样留着。一条陈旧的 `running` 行让「还有作业在跑」一直成立，于是每秒重排轮询、再读、再失败——**一次读失败就足以把这行钉住到进程结束**。

读不到，不等于答案是空列表。事件现在携带 `Option`，失败路径报 `None`，而 `None` 会丢弃缓存行并停止时钟。这行存在的意义是回答「作业还在动吗」；一个本会话已经观察不到的行，不是它还在运行的证据。

## 并行工具结果以一轮的形式发给 Anthropic

当一轮里同时跑了多个工具时，它们的 `tool_result` 块作为一条用户消息紧跟在原用户消息之后。Anthropic API 要求这些块开启下一条用户消息、且只能是开头那一条，因此请求形状是错的。现在连续的用户轮会被合并，结果中的媒体也留在结果内部。

## 非 ASCII 字符不再让光标错位

一个宽度超过一格的符号之后，内部后端自己的光标移动可能从错误的列开始，使预测偏一格。现在每个非 ASCII 符号之后都会重新开始一段，从而在真实单元格上重新同步。这里按「是否非 ASCII」切分而不是按宽度表的判断，是因为决定光标实际移动多远的是终端，而不是宽度表。
