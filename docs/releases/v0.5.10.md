# miao v0.5.10

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.10.zh.md)

v0.5.10 is a patch that stops a busy ledger from interrupting a healthy turn.

## What was interrupting turns

Turns were ending as `interrupted` with no error and no explanation, right after
the assistant's step had been committed and before its tool calls ran: "Tool
'bash' was not executed: the turn stopped before it ran."

The journal showed why it looked like nothing had happened: those runs carried
no `run.cancel_requested` event at all, while every Escape interrupt records
`reason=operator`. The finishing write still passed the lease fence, so no other
window had claimed the Session either. That left one path — the claim renewal.
A drain renews its Session lease every two seconds, and any error from that
renewal cancelled the whole turn, without recording an origin and without a log
line.

## Why the renewal failed

A renewal was a bare `UPDATE` on the shared ledger, so it waited at most the
store's five second busy window. On a multi-gigabyte ledger with several windows
writing, one write transaction that holds the lock longer than that makes the
renewal fail with `database is locked` — and the turn died with it.

Sampling the windows while one of them sat blocked showed both halves of the
stall:

- `WriteTx::commit` ran `PRAGMA wal_checkpoint(PASSIVE)` after every commit. A
  checkpoint holds the WAL write lock that every other writer and every renewal
  need, it ran while the commit still held the cross-process write lock, and it
  ran through a throwaway connection opened and closed for each commit.
- The renewal queued behind the shared store worker, which also serves `git`
  probes and whole projections.

On the ledger this was diagnosed on, write-lock acquires waited 0.5–1.6 s
routinely, and one waited past five seconds.

## What changed

- A renewal is ownership loss only when the store says the claim was fenced:
  that stops the turn and records `lease_lost`. Any other error is a stall — it
  is retried, logged as `lease renewal failed`, and the turn continues.
- The renewal owns a connection and a blocking thread of its own, with a window
  of two lease intervals, so it waits out another window's write transaction
  instead of failing at five seconds, and it never queues behind a `git` call.
- `WriteTx::commit` no longer checkpoints. The runtime merges the WAL on a timer
  once it passes 8 MiB, so an ordinary commit costs a commit.
- The writer's busy window is 20 s, so a maintenance pass makes an ordinary write
  wait rather than fail.
- The TUI names the two engine-decided stops ("another window took over this
  Session", "the Session lease could not be renewed") instead of showing
  `stopped (lease_lost)`.
- A write transaction that holds the lock for a second or more logs the ledger
  and the elapsed time, so a future stall names itself.

## Verification

- `cargo test --lib` in `crates/miao-engine`: 649 passed.
- `crates/miao-engine` integration targets `store`, `session_fence`,
  `concurrent_open`, `http_leases`, `snapshots`, `revert`, `run_admission`, and
  `renewal`: all passed.
- `renewal` holds a foreign write lock for six seconds and asserts that the
  renewal still succeeds; the previous implementation failed at its five second
  window.
- `cargo test --lib` in `crates/miao-tui`: the interruption row names both new
  origins.

## Upgrading

Upgrade if a long turn has ever stopped on its own with "nothing is running now".
Restart every window after upgrading: a window still running an older build keeps
checkpointing on every commit, which is the stall this release removes.
