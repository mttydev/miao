# miao v0.5.1

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.1.zh.md)

v0.5.1 fixes a regression introduced by the 0.5.0 session worktree placement,
and carries the cross-process lease fix that landed just after the 0.5.0 tag.

## The first prompt in a worktree

0.5.0 correctly created a second Session in its own worktree, but admission
still passed the engine checkout as the Session's root. The store compares that
root with the recorded placement and refuses a mismatch, so the first prompt to
a worktree Session failed with `Conflict` — the Session existed and could be
opened, but could not run.

Admission now reads the Session's recorded `engine_location` root and admits
there. A Session without a placement keeps the checkout, which preserves the
behavior of every caller that admits without an explicit initialize; no new
initialization event is written on the admit path. The 0.5.0 placement itself is
unchanged: the first Session owns the checkout and every later Session gets a
detached worktree.

## A live run is never interrupted by a wake

`send_message` with an active wake could make the sending process claim and
recover a Session that another process was still running, marking the owner's
run interrupted. Recovery now only reclaims work whose lease is dead or held by
this process; a live foreign lease leaves the mail in the inbox for the owner's
next boundary. The same rule applies to recovery and questions. Inter-session
waiting also allows 15 seconds instead of 5 for a peer that is actually working.

## Verification

- `cargo test --lib`: 620 passed
- `worktree_isolation`: a placed Session admits at its own root, and a second
  Session is still placed in `.miao-worktrees`
- `provider_failure_quarantine`, `transfer_move`, `approval`: pass after admission
  keeps the stored placement
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`

No engine schema change from 0.5.0. Users on 0.5.0 should upgrade to 0.5.1.
