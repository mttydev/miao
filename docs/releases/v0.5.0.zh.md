# miao v0.5.0

v0.5.0 让并发会话不再共用一棵可写的检出。引擎现在把主检出交给一条会话，其余会话各自放进独立的 detached git 工作树，并由引擎强制执行这条边界，而不是让模型自己发现冲突。

0.5.0 是一次 minor，因为所有者明确要求为这次结构性变更直接升版本。默认仍是 patch 直到第三段到 99 才进位；不能按变更大小或结构自行决定升 minor。

## 一个检出只有一个写者

一棵 git 检出只有一份 HEAD、一份索引和一份工作区。同一个目录里的两条会话不可能都对：一条的 `checkout`、`cherry-pick` 或 `reset` 会把另一条脚下的分支移走，一条的未提交改动也可能被另一条的命令覆盖。看到 detached HEAD 或冲突后停下，并不能恢复已经被破坏的状态。

`engine_checkout_lease` 现在记录唯一拥有检出写权限的会话。placement 在锁内执行，租约是持久化的，所以同一时刻启动的两条会话不会都拿到主检出。归档或删除会释放租约；升级后的老数据库会把租约补给已经在检出里工作的最早一条存活会话。

## 其余会话各自获得工作树

第一条会话保留检出。之后的会话被放进 `.miao-worktrees/<session>`，用 `git worktree add --detach` 创建，因此它带着起始提交但不占用分支。placement 不碰主检出的 HEAD 和 status。该目录会写进 `.git/info/exclude`，所以不会在任何仓库里显示成未跟踪文件，也不需要修改被跟踪的 `.gitignore`。

恢复的会话沿用记录下来的 root。如果它关闭期间检出已被别人拿走，下一轮之前会重新 placement。如果工作树被 miao 之外删掉，会新建一棵，而不是悄悄回落到共享检出。非 git 工作区保持原有行为。

## 隔离是强制的，不是建议

会话的工具克隆现在带自己的 root、目录句柄和主检出。文件工具按工作树解析路径，bash 从那里启动，后台作业继承同一个 root。解析到主检出的写入会被现有的包含检查拒绝。

进程工具也会拒绝把 git 重定向到检出的命令：`git -C <检出>`、`--git-dir`、`--work-tree`、`GIT_DIR`、`GIT_WORK_TREE`，以及爬回检出的 `cd`。`git diff A..B` 是版本范围而不是路径，仍然可用。已经在共享检出里的会话可以调用新的 `worktree_enter` 工具，把自己的文件迁进独立工作树（存储不搬家），同时释放原租约。

## 升级注意

引擎 schema 从 26 升到 27。启动新构建前，先关闭仍持有旧存储的 miao 窗口；迁移会拒绝在有活写者时运行。已存在的会话在恢复时，如果检出已被另一条会话拥有，会重新获得自己的工作树。

工作树不会自动删除：它们装着会话的文件，删除保持显式（`miao worktree remove` / `worktree_remove` 工具，仍有会话工作时会拒绝）。
