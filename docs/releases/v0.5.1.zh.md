# miao v0.5.1

v0.5.1 修复 0.5.0 会话工作树 placement 引入的回归，并带上 0.5.0 tag 之后合入的跨进程租约修复。

## 工作树里的第一条 prompt

0.5.0 能把第二条会话正确放进独立工作树，但 admission 仍把引擎检出当作会话 root。store 会把传入 root 与已记录的 placement 比较，不一致就拒绝，于是工作树会话的第一条 prompt 直接报 `Conflict`——会话能创建、能打开，但跑不起来。

现在 admission 读取会话已记录的 `engine_location` root，并在那里 admission。没有 placement 的会话仍使用检出，保持所有“不显式 initialize 直接 admit”的调用方原有行为；admit 路径不再额外写初始化事件。0.5.0 的 placement 本身不变：第一条会话拥有检出，之后的会话各自获得 detached 工作树。

## 有活租约的 run 不会被唤醒打断

`send_message` 的主动 wake 可能让发送方进程抢到 claim 并 recover 另一进程仍在跑的会话，把对方的 run 标成 interrupted。现在只有在租约已死或由本进程持有时才回收；外部活租约会把邮件留在收件箱，由所有者下个边界领取。recovery 和 questions 使用同一规则。跨会话等待也从 5 秒放宽到 15 秒，给正在工作的 peer 留出时间。

## 验证

- `cargo test --lib`：620 passed
- `worktree_isolation`：已 placement 的会话在自己的 root admission，第二条会话仍落在 `.miao-worktrees`
- `provider_failure_quarantine`、`transfer_move`、`approval`：admission 保留已记录 placement 后全部通过
- `cargo fmt --check` 与 `cargo clippy --all-targets -- -D warnings`

引擎 schema 与 0.5.0 相同。使用 0.5.0 的用户应升级到 0.5.1。
