# miao v0.3.79

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.79.md)

v0.3.79 让文件快照优先借助 git；并把 workspace 记忆存储彻底接入引擎：模型可以主动保存与召回事实，上下文带着它们穿越压缩与重启，还有一个可选的轮次边界通道自动提取持久事实。

## 文件快照优先 git（#3088）

三阶段 revert 之前把每个捕获的文件都存成引擎侧 blob，上限 8 MiB——超过上限的跟踪文件会被记成「不可恢复」，files 阶段的 revert 会直接把它删掉。现在捕获时会探查仓库：被会话触碰、且在 HEAD 处保持干净的跟踪路径，改记 `git:<sha>` 引用而不写 blob，恢复时用 `git show` 取回，任何大小都成立。脏文件、未跟踪文件和被 gitignore 的路径仍走精确内容的 blob；非 git 工作区行为完全不变；git 探测失败或超时则回落，不会卡住捕获。仓库 HEAD 随每次捕获结果一起返回。

## 会话可以记忆了（#3089）

memory 存储层迎来了它的调用方。`memory_save` 持久化一条持久事实（拒绝完全重复，单条上限 500 字符）；`memory_recall` 按子串过滤列出活跃条目。系统上下文通过同一条授权读路径携带一个有界的 `<memory>` 块，保存的事实因此能穿越压缩与重启，块头也向模型说明这两个工具的存在。

自动提取藏在 `memory.auto_extract` 之后，默认关闭。开启后，每 N 轮正常完成的 assistant 回复（默认 10 轮）会派生一个后台通道，向模型请求持久事实、宽容解析 JSON 数组、限量并去重，然后追加未评审的 `auto: true` 条目，交给操作者评审。该通道从不被等待——不可能阻塞或搞砸当前轮——并挂在进程级停机令牌上。

## 只会回答 "waiting" 的 goal 循环停下了（#3087）

goal 通道若一直回答 "waiting"，会无限重新武装自己；现在循环会停下，而不是把预算空转掉。
