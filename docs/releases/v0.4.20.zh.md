# miao v0.4.20

v0.4.20 把启动页重做成会话自身的版式，修复「一轮对话被画两遍」的问题，把受阻/等待的工作移到输入框上方的独立状态行，新增 ChatGPT 登录，并修掉 `miao session find` 的过期索引。

## 启动页就是会话的版式

过去的启动页是一块独立屏幕：横幅、事实列和一个裸提示框，第一条消息发出去后立刻变成另一套布局——侧栏、封闭输入框。现在它从第一帧起就用会话的完整 chrome 渲染：欢迎头（产品字标、版本、记住的模型与 provider、工作目录、告警）画进空转录区，随第一条消息一起滚走，会话开始时没有任何跳变。还没有会话的侧栏照常显示工作区块；提示框 `max_width` 的 `auto` 语义改为「撑满列」，不再是「居中 70%」。

## 一轮对话只提交一次，就只画一次

两个缺陷会让转录把同一内容显示两遍，而引擎只提交了一份。

同一次 run 内的 provider 重试会保留失败那次的临时流：`App::stream` 只在 `run_id` 变化时才新建草稿，`provider.retry` 帧只改状态相位，失败那次已流入的 Thought、文本和调用留在草稿里，重试又把同样内容追加一遍——某个对着不稳定端点的会话重试到 82 次，看起来就像反复做了同一个计划。现在 `provider.retry` 到来时先丢弃临时草稿再让新尝试流入；`provider.waiting` 心跳仍刻意保留草稿，长等待不会把文字闪空。

另一个独立缺陷：转录投影只保留 200 条消息的滑窗，而淘汰流式草稿的规则数的是窗口内 assistant 条目的数量。旧消息滑出后，一次提交可以不改变计数，已提交的消息和它自己的流式草稿就同屏共存。现在草稿的退场改为对照转录里最新的 assistant 序号，滑窗无法再误读。

## 受阻与等待移到输入框上方

待办里标了 `blocked` 或 `waiting` 的条目过去画在输入框首行——带着警告色的提示坐在边框盒子里，读起来像已输入的内容。现在这条提示画在框上方自己的状态行：`受阻` 保留请求操作者处理的警告色，`等待中` 保持弱化灰色（等待中的会话仍在前进），空框恢复轮换的占位示例。状态行随待办状态出现/消失，与编辑器无关，打字不会引起布局跳动；可执行的「下一步」仍留在框内，因为 `Tab` 会把它填进草稿。

## ChatGPT 订阅可以登录了

ChatGPT 订阅此前进不了 miao：设置对话框能存 API key，但 OpenAI 账号授权不是 API key，也没有任何东西把它路由到 ChatGPT 后端。`miao auth login openai --oauth` 启动设备码授权，为无头 shell 打印 URL 和代码，有浏览器时自动打开，并保存得到的 OAuth 凭据。已存的 OpenAI 账号现在自己产出 `subscription-responses` 路由——登录即完成全部配置。

## `miao session find` 改用 SQLite 的变更计数器

`sessions-index.json` 缓存靠文件长度和修改时间判断工作区账本没变。但迄今为止每次插入都让账本停在恰好 20480 字节，同一毫秒内的两次写入 mtime 相同——多了一条会话的账本可能与建索引时的账本同戳，查找就会对明明存在的会话回答「找不到」。现在时间戳包含 SQLite 的 `data_version` 变更计数器，每次提交都会移动。
