# miao v0.5.3

v0.5.3 改的是终端对你的回应：消息按下回车就出现，会话列表不再挡住一轮对话，需要你动手的步骤会主动提问、并说明怎么继续，而不是把会话留在看起来卡住的样子。同时让目录在冷启动时不再扫描消息历史。

## 消息按下回车就出现

过去对话区要等到「引擎已接收并提升这条输入」的投影到达才认识这条消息，所以回车之后什么都不显示。在 4.3 GB 的库上，最近四十个新会话的首条消息在会话行之后 0.7–1.3 秒才出现；其中一个的消息排在冷的会话列表读取之后，等了 6.1 秒。

现在输入框在回车的瞬间把消息放进框上方的待处理带，用的就是它将被接收的 id。列出该输入为待处理的投影、或携带已提升消息的投影，会替换掉这条回显——所以文字不会出现两次，也不会闪。被取消或被拒绝的输入立即消失。

## 列表不再挡住一轮对话

会话目录是一次整库读取，缓存冷时要几秒，而两个请求循环都是一次只处理一个请求：排在列表后面的消息要等整次读取，给首个消息命名还会在路径上再排一次读取。

现在引擎用自己的任务回答 `session_catalog`，stdio 循环同时继续处理请求、轮询事件，并在关闭输出流前等待在途的读取。TUI 在克隆的客户端上后台读取列表；乱序完成的读取会被丢弃，只有最新的会生效。

## 受阻的步骤会提问，并说明怎么继续

清单里等你动手的步骤过去只以一行提示结束回合，而空输入框还在轮换无关的示例，于是状态看起来像卡死。

- 默认提示词（没有家族提示词时的回退）现在要求：需要你决策、只有你能做的动作、或代理没有的权限时，用 `question` 工具给出具体选项——包括「已完成，继续」——并在同一回合按你的选择继续。
- 待处理行的结尾显示「回复继续」。
- 等待或受阻时，空输入框显示「回复以继续…」，不再给示例。
- 受阻条目按条目去重提醒一次，且只发给没有焦点的窗口。

## 每个会话一行，提交时保持

目录预览过去会扫描每个会话最近二十条消息：四十个会话读出 4.63 MB 内容，平均每个约 116 KB，这就是冷启动打开列表的代价。

现在 `engine_preview` 为每个会话保留一行，在产生它的文本提交时写入（只有工具调用的回合不覆盖）。revert/unrevert 会按仍然可见的消息重写。

**升级提示：** schema 升到 28。升级后第一次启动会为每个既有会话回填一次预览——4 GB 的库大约一两秒——此后列表不再扫描消息历史。

## 本次还包括

- 标题栏直接读 `.git/HEAD`，首帧前不再起 `git rev-parse` 进程。
- Anthropic 以本版本不认识的 stop reason 结束回复时，回合正常结束，而不是在内容已经到达后报错；没有给出 reason、或流里还有工具调用的，仍然报错。
- 会话列表在模型目录之后加载，普通启动先显示模型再读列表。
- 绘制一帧时隐藏光标，避免它闪在旧位置。
- 图片对每个模型都先提供；拒绝图片的模型用自己的提示降级，而不是把消息压住不发。
- 退出终端时恢复 shell 继承的终端状态。
