# miao v0.3.92

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.92.zh.md)

v0.3.92 makes a resumed Session look like the one you left, lets a long implementation run past the stale-list guard, and stops a wedged CI leg from holding a release hostage.

## A long implementation is no longer stopped as a stale list

The todo-stale guard stops a drain once the persisted list has been unchanged for twelve provider turns. Twelve was chosen from a Session that drifted for 176 turns, but it also stopped Sessions that were working the whole time: one closing out a release, and one implementing a single `in_progress` item across a dozen tool calls. Both needed an operator message to resume work that was never adrift.

The bound is now 24. It still reports the shape of failure the guard exists for — the same drift now stops at 24 turns instead of 176 — while a long implementation stretch no longer reads as a stale list. The gentle reminder after three turns and the firm instruction after eight are unchanged.

## A resumed Session no longer returns as a wall of pause rows

Every recorded `loop.stopped` painted its own `⋯ context · engine` row, and resuming with `miao -s` replays every stop the Session ever recorded. A Session that paused once per turn while it waited on background jobs came back as a column of identical `paused: waiting` blocks — 51 of them in one 0.3.91 Session — with the conversation buried underneath.

A pause is a status fact, not a message: the engine already persists the full notice as injected context, where the operator can still read it. The view now keeps exactly one pause row, the newest, so a resume looks like the Session you left.

## Release plumbing that recovers on its own

Two infrastructure failures hit the same release and both needed an operator to cancel and re-run by hand. The automatic retry now inspects a run's jobs instead of its overall conclusion, so it also reacts to a single leg cancelled while the rest of its run kept going, and to a wedged self-hosted leg killed by its own job limit. A real failure still leaves the run red.

The release gate also outlasts that recovery now: it waits 150 minutes, enough for one job to reach its hour limit and its retry to finish, instead of refusing a green commit at 45 minutes. A test derives the budget from the CI plan, so a future job cannot silently outgrow it.

## Windows stops failing the cancel-authority fixture on load

Two cancellation tests timed out at five seconds on the Windows release gate while 579 other tests ran beside them, and passed on a re-run. That wait is the fixture's start-up budget rather than a boundary assertion, so it is now sixty seconds; the tests that measure how quickly a cancellation lands keep their short deadlines.
