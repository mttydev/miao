# miao v0.5.19

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.19.md)

v0.5.19 是一个修复版本：大 ledger 上每次 run 结束时的数秒写入停顿已消除。

## 结束 run 不再全表扫描工具表

每次 run 结束都会查询该 run 计划中或已派发的工具。`engine_tool` 此前只有主键索引，这条查询会扫描整张表。被报告的 3.5 GB ledger 有 95,829 行、64 MB 工具输入：在副本上耗时 3.25 秒，也是多个窗口共用 ledger 时 10–16 秒写事务的主要部分，进而拖住投影、让画面落后于日志。

现在 `engine_tool` 带 `(run_id, state)` 索引。同一查询变为 `SEARCH`，在副本上耗时 0.00 秒；同一事务里把中断工具标记为 unknown 的更新也会走这个索引。

## 一次性索引构建

索引放在幂等的 schema 批量语句中，而不是带版本号的迁移。已有 ledger 第一次打开时会构建一次——3.5 GB 副本上约 3.4 秒——之后每次打开都是空操作。因此升级不需要先关闭其它所有 miao 窗口。

## 验证

- `tool_index_tests`：2 个通过——reconcile 查询计划使用索引；索引被删除的 ledger 下次打开会补建。
- miao-engine 653 个 lib 测试；clippy 无告警。
- 被报告 ledger 的副本：全表扫描 3.25 秒 → 索引查找 0.00 秒。
