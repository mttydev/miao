# miao v0.5.16

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.16.zh.md)

v0.5.16 is a patch that makes `miao -s <id>` start in a fraction of the time.

## What was slow

The storage index maps a Session to the ledger that holds it, but every launch validated all 523 ledger stamps first. A busy ledger is always one write behind the cache, so the check failed and every database was scanned: `miao session find <id>` took 1.31 s, and `-s` spent the same time before the first frame.

## What changed

A cached hit is verified against the one ledger that claims it: open it read-only, confirm the Session is still there, and read its current root so a re-homed placement opens the right tree. Any doubt — no index, an unknown version, no candidate, a ledger that no longer holds the Session — falls back to the existing scan, so a stale cache costs time but never correctness.

Measured on one machine: `session find` 1.31 s → 0.01 s, and the first alternate-screen frame of `-s` 1.16 s → 0.21 s.

## Verification

- Three new locate tests: a ledger changed behind the cache, a re-homed root, and a deleted Session falling back to the scan.
- miao-cli `--bin miao`: 73 tests pass; clippy clean.
