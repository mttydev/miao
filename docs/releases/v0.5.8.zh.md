# miao v0.5.8

v0.5.8 改变了会话默认能读到什么，并恢复了用于授予工作区外只读访问的 `references` 配置。

## 文件读取默认跟随 OS 用户

`read_file`、`read_image`、`list_files`、`glob`、`grep` 原本被锁在会话根目录里：根目录之外的路径一律按“工作区外”拒绝。工作树放置（#3360）把并发会话放进 `.miao-worktrees/<session>` 之后，会话连自己来源的主检出都读不了，任何外部路径都要先有显式授权。

现在读取默认使用 `readScope: "host"`：会话能读本 OS 用户可读的任意文件，包括另一个检出。写入仍然是单一所有者——文件写入、`apply_patch`、knowledge/memory 存储、命令的工作目录都留在工作区内。`readScope: "workspace"` 恢复旧的收窄（工作区 + 只读引用），拒绝信息也会直接点名这个开关，而不只是陈述规则。

## 配置的 references 重新到达引擎

`miao.jsonc` 里的 `references` 是会话可在工作区外只读访问的路径清单。它此前会被解析、也会出现在 `miao debug config` 的输出里，但引擎的读取范围始终为空：TypeScript 宿主原本会写出 `references.json` 清单，引擎以 `--references-config` 读取；该宿主在 #2840 退役后，原生入口没有接手。因此在 `readScope: "workspace"` 下这个键不授予任何权限，系统上下文里也不会列出这些参考。

现在原生入口会用引擎所读的同一套分层文档推导该清单：相对路径按声明它的配置文件所在目录解析，`~/` 通过 home 目录展开，`hidden` 项和不存在的路径不授予权限，git 仓库会被告知并跳过，超过 16 条授权会截断并给出警告，而不是触发引擎自身的上限失败。旧的 `reference` 键仍然有效。四个入口都会收到它——TUI、`miao run`、`miao serve` 与 ACP；显式设置的 `MIAO_ENGINE_REFERENCES_CONFIG` 仍然优先。

## 验证

- `crates/miao-engine` 的 `cargo test --lib read_scope`、`tests/read_scope.rs`，以及 tools、directory、references、context 与 config-reload 测试套件；`cargo clippy --all-targets -- -D warnings` 与 `rustfmt --check`。
- 在 Linux 构建机上运行 `crates/miao-cli` 的 `cargo test`（70 个测试）、同样的 clippy 与格式化门禁，以及两个 PR 的 CI。
- macOS arm64 构建上的端到端验证：默认 `readScope` 下读取工作区外的文件成功并返回内容；`readScope: "workspace"` 下同样的读取被拒绝。带参考配置启动 `miao serve` 时，会在引擎启动前写出符合预期的 `references.json` 清单。

## 升级

新的默认值属于行为变更：如果某个部署依赖“读取不出工作区”，请在其配置里设置 `readScope: "workspace"`。项目配置仍然从启动时的工作区（主检出）解析，而不是从每个会话的工作树解析，因此 `references` 要放在主检出的 `.miao/` 或 `~/.config/miao/` 里。
