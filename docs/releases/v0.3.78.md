# miao v0.3.78

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.78.zh.md)

v0.3.78 closes the last way a paused Session could fail its whole run, keeps a rewindable copy of each file before the agent edits it, gives Sessions a durable workspace memory the engine injects into context, and turns the Sessions dialog into a live one-screen view of what each Session is doing.

## A pause no longer fails the run (#3083)

A Session paused twice on the same unchanged todo list while its background jobs fell from two to one. The pause note's durable id was derived from the list's signature and the round alone — and for a `waiting` pause the round is always zero — while its text names how many jobs are still running. The second pause therefore arrived as the same id with different text, which the store rejects as a conflict, and the drain failed with `input id conflicts with an existing admission` before the note could be recorded.

The note's text now joins its identity, and the engine's own `loop-blocked` and `loop-armed` state writes got the same treatment, since their payloads carry changing stall counters and the arrival that lifted the block. An identical repeat still dedupes; a changed note is recorded as the new fact it is.

## Edits keep a checkpoint (#3085)

Before `write_file` or `edit_file` touches a file, the current content is saved under `.miao/checkpoints/` inside the workspace, so an edit that turns out wrong can be rewound to what the file held. Checkpoints are per-file and capped at five, oldest evicted first, and a file that does not exist yet produces none — there is nothing to rewind before the first write.

## Sessions remember workspace facts (#3084)

Agents forget workspace facts across compaction and restart. A Session can now persist them in `.miao/memory.json`: entries start unreviewed, the engine injects them into the system context as a `<memory>` block, and unreviewed entries are marked as such. A corrupted store degrades silently to empty — memory is advisory and never blocks a Session.

## The Sessions dialog is a live agent view (#3082)

The dialog used to list identity only, so watching background work meant opening each Session in turn. It now folds the live rows into its detail line — a dot for a Session whose run is still going, the count of todos that are neither completed nor cancelled, and whether the goal is still armed. Keys stay raw names, so delta sampling and merge behavior are untouched, and the dialog re-asks the catalog at most every two seconds while frames keep flowing.
