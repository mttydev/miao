# miao v0.5.5

v0.5.5 是修对话区与右侧栏之间那条分隔线的补丁。它此前用的是次要文字的颜色，看上去像一条白线；它又紧贴对话区的最后一列，Windows 控制台重编码时可能把它画偏一列，快速滑动时甚至落进右侧栏里。现在它是一道安静的边框，别的绘制也够不到它。

## 分隔线是边框，不是文字

分隔线原来用 `textMuted`（默认主题下 #b9b9b6），那是次要文字的颜色；其余所有边框（包括输入框）用的都是 `border`。现在它也改用边框色，读起来是边，而不是一条亮线。

## 分隔线左边不再排任何内容

对话区此前正好排到分隔线那一列，最后一列的字符可能碰到分隔线的单元格。这不只取决于 miao：Windows 控制台会把整屏重新编码后交给终端，并把变脏的单元格当作上一行的延续输出，只要控制台和终端对某个字符的宽度判断不同，这段输出就会整体偏移。现在对话区在分隔线左侧留出一列，这列和分隔线一起由分隔线自己绘制，任何窗格都不再排在那里。原本会被分隔线擦掉的宽字符，现在也完整保留。

## 滑动的那一帧不再重画分隔线

此前分隔线被强制放进每一帧，用来补回终端可能丢掉的某一行。可它紧挨着正在重绘的转写行，这恰恰是它在 Windows 上被画偏的原因。现在只有这一帧没有移动对话区时才强制重画：滑动的那一帧完全不碰它，之后的安静帧再把整列补上——这也顺便补回被终端丢掉的行。

## 验证

`crates/miao-tui` 的 `cargo test`（库测试与全部 PTY 端到端测试）、`cargo clippy --all-targets -- -D warnings`、`rustfmt --check` 全部通过。颜色与空列各有回归测试，撤掉改动就会失败。重画时机是针对控制台重编码的缓解措施，最终确认需要 Windows 的 ConPTY 会话，而 CI 不跑这一项。
