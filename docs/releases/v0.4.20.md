# miao v0.4.20

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.20.zh.md)

v0.4.20 reworks the landing page into the Session's own layout, stops the
transcript from showing one turn twice, moves held work onto its own row above
the input, adds ChatGPT sign-in, and fixes a stale index in `miao session
find`.

## The landing page is the Session's own layout

The start page used to be a separate screen: a banner, a facts column and a
naked prompt that turned into a different layout — sidebar, closed input box —
the moment the first message went out. It now renders with the Session's full
chrome from the first frame. The welcome header (the product mark, version,
remembered model and provider, workspace directory, notices) paints into the
empty transcript area and scrolls away with the first message, so nothing
jumps when a Session starts. A sidebar with no sessions yet shows the
workspace section as usual, and the prompt's `auto` width now means "fill the
column" instead of "center at 70%".

## One turn, committed once, is drawn once

Two defects made a transcript show the same content twice while the engine had
committed it exactly once.

A provider retry inside one run kept the failed attempt's provisional stream:
`App::stream` only started a new draft when the `run_id` changed, and the
`provider.retry` frame only changed the status phase, so the failed attempt's
streamed thought, text and calls stayed in the draft while the retry appended
the same content again — a session behind a flaky endpoint sat at 82 retries
and read as if it had made the same plan over and over. `provider.retry` now
discards the provisional draft before the new attempt streams, while a
`provider.waiting` heartbeat deliberately keeps the draft so a long wait does
not blink the text away.

Independently, the transcript projection keeps a 200-message window, and the
rule that retired a streaming draft counted assistant entries inside that
window. A commit can leave the count unchanged once older messages slide out,
so a committed message and its own streaming draft stayed on screen together.
The draft now retires against the transcript's latest assistant sequence,
which the sliding window cannot reinterpret.

## Blocked and waiting work moves above the input box

A checklist item marked `blocked` or `waiting` used to paint in the input's
first line: a warning-coloured hint sitting inside the bordered box read as
typed content. The hint now paints on its own row above the box — `受阻` keeps
the warning tone that asks for the operator, `等待中` stays muted because a
wait is a Session still moving — and the empty box goes back to its rotating
example. The row keys off the checklist rather than the editor, so typing
never shifts the layout, and the runnable `下一步` offer stays in the box
because `Tab` promotes it into the draft.

## ChatGPT subscriptions can sign in

A ChatGPT subscription had no way into miao: the settings dialog stored API
keys, but an OpenAI account grant is not an API key, and nothing routed it to
the ChatGPT backend. `miao auth login openai --oauth` starts the device-code
grant, prints the URL and code for a headless shell, opens the browser when
one exists, and stores the resulting OAuth credential. Stored OpenAI accounts
now produce `subscription-responses` routes on their own, so signing in is the
whole setup.

## `miao session find` trusts SQLite's change counter

The `sessions-index.json` cache judged a workspace ledger unchanged from its
length and modification time. Every insert so far has left the ledger at
exactly 20480 bytes, and two writes inside one millisecond carry the same
mtime, so a ledger that gained a Session could carry the same stamp as the one
the index was built from — and the lookup answered "not found" for a Session
that is there. The stamp now includes SQLite's `data_version` change counter,
which moves on every commit.
