# miao v0.4.5

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.5.zh.md)

v0.4.5 completes the merged status row: under the mtty host the terminal reclaims the facts row for the conversation entirely — the composer keeps its bottom edge with no reserved gap — and every press on the host's row arrives as the operator's own chord, spelled by the keymap right in the wire.

## The row belongs to the conversation

Yesterday's merge kept a reserved strip under the composer: an invisible click surface the host aimed synthesized mouse presses at. It worked, but it read as a wasted line between the box and mtty's status row. Under the host the layout is now one band shorter — the conversation takes the line — and the wire reports the facts as labels with the chord each one answers to (`ctrl+x f` flips approval, `ctrl+x m` opens the model picker, `ctrl+x a` the provider list), spelled by the keymap so remaps travel with the report (#3264).

## The approval toggle owns a key

The merged row can press the approval fact, so the flip finally owns a chord of its own: `<leader>f`, next to the picker and list chords it sits beside on mtty's row (#3264).

## Compatibility

A press on mtty's row lands the same way across combinations: a chord-carrying miao sends its named keystrokes; a cell-reporting miao (0.4.3/0.4.4) gets the synthesized mouse press at the recorded cell. A zero-geometry wire is refused rather than clicked onto the transcript. Plain terminals keep the painted facts row exactly as before.

## Maintenance and verification

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and the full `cargo test` suite for the TUI crate run in CI (760 green) under the Rust 1.100 stable toolchain.
