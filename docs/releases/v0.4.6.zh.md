# miao v0.4.6

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.6.md)

v0.4.6 让首次启动从"拒绝"变成"引导"，并让你在回看历史时已提交的回答留在屏幕上。

## 首次启动有地方可去

什么都没配置的启动过去会直接失败：`--model is required`。现在引擎会正常起来，并提供选择器所依赖的两份目录：安装内置的每个 provider 都列出来并标为待授权，模型列表为空，发送提示词会得到与启动错误相同的指引——先存 key，再选模型（#3269）。

存下第一把 key 就够了。引擎会从配置与凭证存储派生路由；已经在运行的引擎会在 `config_reload` 时重新派生，不需要重启。TUI 的内嵌引擎改走这条路径并重读两份目录，因此在对话里存下的 key 会立刻出现在选择器中。宿主写入的路由清单保持原有契约：其中标为 primary 的路由仍必须与宿主启动时的 provider 一致。

## 已提交的回答留在屏幕上

回看历史是阅读位置，不是暂停。读者停在历史中时，一条回答完成了：已提交的投影被整块扣住，而它替换掉的草稿已经被清掉，对话区于是空白，直到按下 End。现在只做追加的新投影——回答、下一条提问——会立即绘制；只有会丢掉已加载条目的刷新才被扣住（#3268）。

滚动夹取也从投影步骤移到拿得到换行后行数的那一帧，视口不会再因为上一帧按未换行行数低估而跳回旧尾部。

## 兼容性

已配置模型的启动解析与之前完全一致。无模型启动是新行为：由引擎而非缺失的参数决定首次运行该提供什么。

## 维护与验证

CI 覆盖 `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、引擎与 TUI 测试套件，以及新增的 `unmodeled_serve` 集成用例：空启动提供两份目录、已存 key 成为可服务路由、运行中存入的 key 经 `config_reload` 成为路由。本地在 Rust 1.100 stable 下，引擎全量（588）与 TUI 全量（766）库测试通过。
