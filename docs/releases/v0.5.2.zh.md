# miao v0.5.2

v0.5.2 让模型目录在两次发版之间也能保持最新，并补上「订阅套餐提供了目录尚未收录的模型」这个缺口。同时带上 0.5.1 tag 之后合入的 TUI 与引擎修复。

## 目录会自己刷新

过去产品只读磁盘上的快照。站点每天重建目录，但一台机器要等到升级才能看到新模型，安装包里的快照也一直停在构建时的样子。

现在 miao 会拉取 `https://mtty.dev/models/api.json`（站点实际提供 JSON 的地址；`/models` 本身是文档页），每天用 `If-None-Match` 重新校验一次，并原子写入 `$XDG_CACHE_HOME/miao/models.json`。目录没变时服务端返回 `304`，不产生下载。返回内容不是目录时不会覆盖磁盘上的文件；连不上站点的机器继续用安装时打包的快照。

`miao models --refresh` 立即拉取一次。终端界面和 `miao serve` 也会在后台刷新，因此长期运行的进程不必等重启时下载就能拿到新模型。

## 套餐自己的模型列表

订阅套餐可能提供目录还没收录的模型。对本机存有 key 的每个 OpenAI 兼容供应商，miao 每 6 小时读取该供应商自己的 `/models` 接口，把目录缺少的 id 补进来。

发现只往目录已经列出的供应商里补 id——不会凭空造出供应商，也不会覆盖已有条目。补进来的模型在目录给出之前没有声明上下文窗口和价格；miao 自维护的 overlay 在发现之后生效，真实条目始终优先。

GLM-5.4 就是这样出现的：coding-plan 接口先提供了它，目录随后才收录。现在目录已带上它（1M 窗口、128K 输出、text/image/video/pdf 输入），所以 0.5.2 同时删掉了当初为它写的临时 overlay 条目——目录里的条目就是唯一来源。

## 本次还包括

- 首页头部跟随第一轮对话，不再被转录内容滚过去。
- 流式编辑等已提交的 diff 再绘制，临时 diff 不再先闪一下。
- 输入框始终标注自己的状态。
- 会话里的 `git` 命令留在自己的工作树内，不再因为提到检出下的路径而被拒绝。
- 新增每周运行的 `catalog-drift` 检查，把自维护 overlay 与线上目录对比：已被目录追平的条目会让检查失败，部分字段冗余会打印出来供清理。

## 验证

- `cargo test --lib`：`miao-engine` 622 passed。
- `catalog_refresh`：5 个用例（200 + `ETag`、304 不重写、TTL 内不发请求、非目录内容保留旧文件、站点不可达）。
- `model_discovery`：5 个用例（id 形状、URL 拼接、合并边界、带鉴权的本地探测）。
- 构建机端到端：`miao models --refresh` 写入 327 个 provider、10,228 个模型，第二次运行报告 `catalog is current`。
- 对线上目录运行漂移检查：通过，没有需要删除的条目或字段。
- `miao-engine` 与 `miao-cli` 的 `cargo fmt --check` 与 `cargo clippy --all-targets -- -D warnings`。
