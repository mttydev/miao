# miao v0.4.7

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.7.zh.md)

v0.4.7 makes the theme list show what it is about to apply, and keeps the approval switch on screen after it is switched off.

## The theme list previews

`/theme` changed nothing until Enter, so picking `kanagawa` from a column of names was a guess. Every row now paints as the cursor reaches it — background, borders, the sidebar and the launcher switch live. Esc puts back the theme the picker opened with; Enter keeps the pick and writes it to preferences. The dark/light/unlock rows still apply on Enter, because they reload the palette catalog rather than swap one theme.

## The approval switch stays

The merged footer — and the strip miao paints itself — named auto-approve only while it was on. One press turned the policy off and removed the only target that could turn it back on. The fact is now always present: auto-approve keeps its warning, the default mode reads `ask approval` / `逐次批准`, and both carry the same chord. A press flips the policy either way.

## Also in this release

Two viewport guards: a detached viewport whose offset outlived a shorter transcript paints its tail instead of a blank window, and opening another Session while reading history follows the new tail (#3271).

## Compatibility

No configuration changes. Themes and preferences work as before; only the moment they are written changed — Enter, not every row.

## Maintenance and verification

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, and the full TUI suite (767 tests) pass on Rust 1.100 stable.
