# miao v0.3.76

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.76.md)

v0.3.76 在 TUI 退出时终止引擎子进程，杜绝旧引擎守护进程悄悄撤销操作员的更新。状态条折叠进输入框边框；反复出现的粘贴图片卡死与 `input id conflicts` 失败已消除；无效工具输入会点名字段；压缩可从存储侧诊断；桌面端开始流式输出回答、支持选模型、文案走共享 i18n。

## TUI 退出时引擎跟着终止 (#3072)

TUI 启动时把 miao-engine 作为子进程生成。TUI 退出后，引擎变成孤儿守护进程，继续跑启动时的旧二进制。操作员更新 miao 后重启 TUI，TUI 重连到的仍是旧引擎守护进程——后者静默使用旧算术，更新带来的修复全部无效。

Connection 现在保存生成的子进程并在 Drop 时终止。引擎生命周期与 TUI 一致：退出 TUI 引擎就终止；重启 TUI 生成新引擎（当前二进制）。会话数据在 SQLite 中持久保存，操作员回到原处继续。

## 状态条折叠进输入框边框 (#3067)

状态条原本是输入框下方的独立行，占用一行垂直空间且读起来像第二条 chrome 条。输入框标题本就携带运行阶段、队列深度和通知；状态条的事实现在折叠进输入框**底部**边框——状态提示、模型（强调色）、轮次与花费——右缘是 `miao <version>`。对话区收回状态条占用的一行；leader 组合键等待期间仍会接管这一行显示和弦菜单。

## 桌面端流式输出与管理 (#3059–#3063)

桌面窗口现在从引擎的进度帧流式输出回答（#3063）、从表头选择会话模型（#3061）、文案走共享 i18n 层（#3059）、对话以聊天产品形态呈现（#3062）。

## 粘贴图片卡死输入框已关闭 (#3069)

粘贴截图后、剪贴板读取完成前快速回车，提示词被挂起；图片落地、挂起的提示词真正发出时，草稿连同 `[Image 1]` 标记仍留在输入框里，composer 还握着图片字节——看起来像没发出去，诱导同一提示词发两次，下一次粘贴又在旧标记旁追加第二个标记。现在挂起的提示词真正发送时会把输入框清空；被拒绝的分支仍会把草稿还给输入框。

## 反复出现的 "input id conflicts with an existing admission" 已消除 (#3074)

一个 run 会经历多次 drain 激活（等待 → 后台通知 → 继续），引擎内部自续输入的身份计数器按激活各自重置，而存储里的行依然存在——两个激活在同一 id 上竞速；一旦 pause 把该行取消，另一激活的再准入就以 `input id conflicts with an existing admission` 失败整个 run。现在每个内部自续 id 都带按次唯一的 uuid，且准入冲突会在 run 日志里点名 id 与所撞状态（`in_xxx exists as cancelled`），不再是裸消息。

## 无效工具输入会点名字段 (#3071)

写入携带 schema 未声明的字段时（`verified` 随每条 todo 回显出现），旧回答是裸的 `invalid tool input`，模型反复重发同一调用。现在的拒绝会点名字段与位置：`invalid tool input: todowrite does not accept todos[0].verified`。

## 压缩可从存储侧诊断 (#3065, #3068)

摘要 pass 现在会持久记录 `compaction.started`，熔断器打开的时段也会记录 `compaction.skipped`——"这个会话为什么没压缩" 直接查 per-workspace 存储即可回答，不再依赖引擎日志。日志未增长时 usage-report 扫描会跳过自身（#3068）。

## 中文输入法确认不再误提交 (#3064, #3066)

输入中文后按回车确认组词会直接提交消息。所有文本域现在跟踪组词状态，Enter/Escape 受其约束。
