# miao v0.3.93

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.93.zh.md)

v0.3.93 fixes the pause row that stayed on screen after the Session had already resumed.

## A resumed Session no longer claims to be paused

A classified stop painted one `⋯ context · engine` row reading `paused: <reason>` above the composer. The row is a state, not a message, but nothing removed it when the state ended: a continuation cleared the transcript's own field and left the painted row behind, and a new drain cleared neither. A Session that paused while a background job ran, then resumed and finished its next turn, kept `paused: waiting` on screen beside "Worked for 6.2s" — reading as if it were still parked.

The row now exists exactly as long as the state does. One helper clears both the field and its row, and runs when the loop re-arms and when a new run starts. The engine's injected notice stays in history, so the detail is not lost.
