# miao v0.3.89

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.89.md)

v0.3.89 让会话在停下时说清原因，拒绝"推脱式阻塞"，也不再把它自己重复的结论读回给模型。

## 停下是可见的，推脱式阻塞会被拒绝

一次 drain 结束总有原因——被阻塞的项、没变化的清单、仍然 open 的目标——引擎本来就记录了它。但对话区忽略了这条记录，于是"停住的会话"和"空闲的会话"看起来完全一样：现在 `loop.stopped` 会以一条 `engine` 记录出现在对话里（`paused: blocked · <item>`、`paused: goal-open`），按 seq 去重，下一次续跑会清除它。

`blocked` 状态现在必须点名模型无法改变的外部依赖：硬件故障、断电、离线、需要人持有的凭据或授权、第三方不可用。"一次回复写不完"、"太复杂"、"需要很多步骤"会在写入层被拒绝，因为接受它就等于让操作者已经批准的会话停摆。引擎自己写的暂停带 `loop: ` 前缀，仍然豁免。

## 重复的结论不再被喂回去

模型用同一段结论结束一轮、又用同样的话开始下一轮，等于把同一件事说两遍；而它读回的那份对话会教它继续这样。现在请求副本会丢掉"紧邻上一轮完全相同"的 assistant 消息。带工具调用的消息永不丢弃，用户回合或工具结果会打断比较——真实工作两侧的相同措辞是两个回答，不是回声。持久记录保留每一行。

## 更少的裁剪，更少"像卡死"的等待

`context.trimmed` 在 2,115 个回合里写了 11,306 次，因为裁剪一旦"刚好不超预算"就停：历史停在上限下一条消息的位置，下一步的工具结果又把它顶回去。现在裁到预算的九成，一次裁剪覆盖若干步。

长但正常的等待也不再与卡死难以区分：超过 90 秒，状态行会写 `仍在 provider 窗口内 · Esc 中断`，这在任何请求体积余量之前都是成立的。

## 侧栏说的是它真正在数什么

清单全部完成后，标题显示 `TODO done n/m`，而不是在新指令旁边继续显示 `TODO n/m`。（`decisions` 改名与上下文选择去重已在 0.3.88 发布。）
