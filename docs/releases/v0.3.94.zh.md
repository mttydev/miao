# miao v0.3.94

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.94.md)

v0.3.94 收尾了循环控制的几处账：只读排查不再被当成停滞的会话，压缩不再把同一回合的回复计两次，聊天区与侧栏之间的分割线在每一行都站得住。

## 只读排查不等于停滞

no-progress 守卫原先只把“派发了非只读工具”当作干活，于是每回合打开一个新文件仍被算作空转回复，两回合后就可能被停下。它现在与 stale-list、flat 两条判据共用同一个信号：执行了一次此前没有执行过的工具调用就是工作。真正的纯文本回复仍会在两回合后触发停止；操作者的下一条消息也会把“重复调用”整套护栏一起重置——拒绝计数不再比与它配套的重复计数活得更久。

## 压缩不再把回复计两次

上下文锚点把 provider 的输入与输出 token 相加，可输入本就覆盖整段 prompt，而消息标记又是在回复落库之前取的。于是同一回合的回复作为 pending 又被计了一遍，每个边界都提前一个回复触发压缩——大窗口下可以忽略，小窗口下影响明显。锚点现在只计 prompt。

压缩断路器也自称统计“连续失败”，但成功提交的那次会保留半开额度：之后一次失败就会让刚刚成功的断路器再次断开，持久化的断路器永远不回到空闲。现在成功提交会清零失败计数。

## 分割线最后绘制

Windows 上聊天区与侧栏之间的竖线会断开，触到窗格边缘的行还会把自己的颜色留在里面。这条线是两列的边界，不属于任何一列，所以现在它是整帧最后绘制的内容：一列、页面底色、每一行都画。任何一列的内容都无法再打断它或给它染色。
