# miao v0.3.87

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.87.md)

v0.3.87 让停下来的会话说清为什么停，并把"真阻塞"和"拒绝拆解"分开。

## todo 全 blocked 时不再无声停摆

"没有可跑项"本身是有歧义的：可能是做完了、列表是空的，也可能剩下的全部被阻塞。续跑循环对这三种情况一视同仁，于是一个仍然 `active` 的目标可能停在那里、没有任何东西推它，直到操作者再次输入。

`blocked_work()` 回答第三种情况，给出每个被阻塞项以及它仍在等待的依赖。现在 goal 仍 active 且无可跑项时，引擎会注入**一次**续跑，点名第一个阻塞项和解除它所需的步骤，并写入 `loop.stopped` / `loop.blocked` / `loop.continuation`；同一份 todo 列表不会重复注入——既有的 stall 与 no-progress 守卫仍然为循环设上限。

## 真阻塞不是拒绝拆解

`blocked_on_external_work()` 按证据给阻塞分类。硬件故障、断电、需要人持有的凭据或授权、第三方不可用：这是阻塞。"一次回复写不完"、"太复杂"、"需要很多步骤"：这是拒绝拆解；两者同时出现时，范围词优先。

## 规格：什么叫做完

`specs/anti-splitting.md` 固定了一条 drain 结束前必须满足的判定——没有 active 的 goal、没有可跑的 todo、没有"未完成 todo 的计划步骤"、没有被阻塞却未提示的项——并为每条加按签名的幂等键，使续跑不可能重复；计划步骤还必须达到"可验证交付物"的粒度，避免用微步骤绕过闸门。

## 本次发布不包含

请求级"完整任务"提示词在发布前已回退：把它注入每一个普通请求会改变 goal loop 测试所依赖的请求形状。它表达的约束不由本版本强制执行；将来强制执行的是规格里那条判定。
