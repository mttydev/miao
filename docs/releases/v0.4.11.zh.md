# miao v0.4.11

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.11.md)

v0.4.11 让自动压缩在路由真正可发送的输入边界上触发，让压缩失败说明原因，并刷新了默认配色与工具行间距。

## 压缩在真实输入边界上触发

声明的 `limit.output` 是模型的上限，不是每一轮实际请求的额度。有些 provider 会接收它（Anthropic 要求 `max_tokens`），OpenAI-compatible 路由则根本不发送输出上限。旧逻辑却把整份声明从窗口里扣掉：一个声明 `output: 393216` 的 1M 路由按 655,360 规划，在 622,592 就压缩——在用户看到的窗口里只有 59%——而同一端点对该模型实际接受过 941,198 tokens 的请求。

现在模型路由会记录 provider 是否真的接收声明的上限。接收时仍全额预留；不接收时按窗口的 1/16 预留，足够容纳端点自己的补全默认值。上面这条路由的触发点因此移到 933,888（窗口的 89%），仍低于端点实际接受过的最大输入。请求上限、界面百分比与摘要角色容量继续读取同一个 ceiling。

## 压缩失败会说明原因

摘要器拒绝一次自动压缩时，旧行为只是静默清掉状态阶段：对话在历史中间停住，没有任何一行说明为什么没有压缩，看起来就像压缩从未发生。失败原因现在会以 `Compaction failed · <原因>` 显示在输入框的提示里，同时运行中的行与阶段照常清除。

## 更安静的默认配色

默认主题重新绘制，画布、面板与语法色彼此一致，并与深色终端背景对齐。明暗两套变体共用同一组角色名，代码块语法断言也随调色板更新。

## 工具行之间留出呼吸

带标签的工具面板让连续两次调用挤成一块：转录仍把单行工具首尾相接。现在每个调用前都有一行空白，堆叠的面板彼此分明。

## 更安静的 diff 与徽标配色

变动的 diff 行改用深绿/深红底色，只有标记保留最醒目的色相。行号与折叠的 hunk 头改为读取各自的主题令牌，而不是借用次要文字色；每个工具标签统一使用一枚实心徽标，不再按调用类别换色。主题可以声明 `toolBadgeBg` / `toolBadgeFg`，原本声明却未被渲染使用的 `diffLineNumber` / `diffHunkHeader` 现在真正生效。
