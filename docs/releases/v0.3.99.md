# miao v0.3.99

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.99.zh.md)

v0.3.99 stops a model's fabricated "context window is exhausted" excuse from parking a session: the engine now corrects the claim with its own measured occupancy and keeps working.

## The fabricated exhausted-window stop

Sessions on weaker models ended their autonomous stretches by announcing the context window was full and recommending a new session, while the sidebar showed occupancy far below the compaction threshold — one long mapping session declared the window exhausted at 61% of 868.9k. Automatic compaction was never the problem: the session had already compacted once, the trigger fires before the window fills, and the engine has no mechanism that requires a new session. The stop was the model's own rationalization, and because the loop's text-only pause carried nothing that contradicts it, the claim reached the operator sounding authoritative, backed by invented reasons.

The drain now checks a text-only reply against the engine's own occupancy. When the reply claims the window is exhausted (a conservative bilingual match: a window word alongside an exhaustion word, or an explicit hand-off to a new session) while the measured count is under the compaction threshold, the loop continues with a correction that states the measured fact — the context window carries X of Y tokens (Z%), against a compaction threshold of T — and instructs the model to continue with tools rather than hand off (#3229). The correction is bounded at two per prompt; a claim that repeats past the bound pauses the session with the same measurement, so the excuse arrives alongside the numbers that contradict it, and `/compact` remains the manual escape hatch. Without a measured occupancy, or once occupancy crosses the threshold, behavior is unchanged and the compaction gates own the situation as before.
