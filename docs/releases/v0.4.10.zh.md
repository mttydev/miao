# miao v0.4.10

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.10.md)

v0.4.10 修好的是同一种情形：Anthropic 端点在合法、只是不常见的方式下收尾，而 miao 把它当成了故障——输出用尽被截断、端点主动暂停、thinking 签名因为历史被改写而失效、无参工具调用被读成非法 JSON。另外，Anthropic 请求的输出上限不再被固定为 4096。

## 截断或暂停的回复改为续跑

Anthropic 解析器只接受 `tool_use`、`end_turn`、`stop_sequence`，而 Bedrock 解析器还接受 `max_tokens`。撞上输出上限不是流损坏：可见内容有效，流中的调用则是不完整的。旧行为是报 `invalid provider stream: incomplete or unsupported stop reason`，整轮结束且没有任何回答。

现在 `max_tokens` 与 `pause_turn` 走和 Chat 截断相同的续跑路径：推理与正文入库，未完成的调用不执行，回合从持久历史继续，只重做剩下的部分。`refusal` 会把拒绝文本原样交给用户；未知的 stop reason 会写明具体取值，而不是藏在 "unsupported" 背后。

## thinking 签名失效不再让会话卡死

Anthropic 把带签名的 `thinking` 块绑定在它生成时的对话前缀上。只要更早的某条消息被改写——工具输出裁剪、兜底截断、注入的提示、切换模型，或一次重新拼装历史的重试——它之后所有签名都会失效，后续请求再也无法满足端点：

```text
messages.19.content.0: Invalid `signature` in `thinking` block.
The block is bound to a different conversation.
```

端点自己给出的补救就是「移除该块」。miao 现在会把这一轮剥离 reasoning 后重放一次，把这次恢复作为 provider retry 记录下来，并且不再为这种确定性拒绝浪费一次「原样重放」的自愈请求。持久转录仍保留推理内容，只有发给端点的副本去掉它。

## 「没有参数」是一种回答

模型调用无参工具时不带参数，空参数串会被读成非法 JSON。一轮里出现三次，会话就会以「模型反复产出非法 JSON 工具参数」暂停——把正确的调用形状当成了缺陷。

现在空参数解出空输入；这份输入是否可用由工具自己的 schema 判断。调用仍然绝不会从周围的文本里借用另一个函数的参数。

## 声明的输出上限生效

Anthropic 要求显式 `max_tokens`，而 miao 一直发 4096，因为设置它的方法在生产路径上从未被调用。扩展思考的 token 计在这份预算之内，所以一轮很长的思考可以把上限整个吃掉，交回一个截断的回复。模型路由声明了每个模型的 `limit.output` 时，现在会转交给 Anthropic 解析器；不接收该上限的 provider 保持自己的默认值。
