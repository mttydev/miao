# miao v0.3.91

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.91.zh.md)

v0.3.91 closes the three ways a Session could stop without telling the operator what to do, makes an oversized request cheaper to fit, and stops paying for diagnostics nobody reads.

## A checklist nobody reconciles is stopped

The stall guard only measured a repeated text-only reply, so a tool-driven Session ran **176 turns** with an untouched 14-item list while every turn carried a gentle reminder. A list that still has open items and has not been rewritten for 12 provider turns now stops the drain with `loop.stopped{reason:"todo-stale"}` and a note naming `todowrite`. After 8 turns the reminder itself escalates into an instruction to reconcile before any further tool call. A finished list, or a Session with no list, is never stopped.

## A spent Goal budget names the command that lifts it

The Goal budget stops before the first provider turn, and the tool that could rewrite it needs that turn — so the stop note advised a move the product did not have. It now names `/goal budget <turns>`, which writes a new Goal revision and resumes the Session with the input already waiting.

## An oversized request is pruned before it is trimmed

When a request no longer fits, the runner first elides tool output above 16 KB outside the newest turn, oldest first, until the outgoing request reaches the window budget; whole-message trimming then handles what remains. A Session whose request fits is untouched, so its cache prefix stays stable, and the durable transcript keeps every byte. A context-length refusal also skips the one HTTP-400 self-heal replay, because the overflow path already compacts and retries with a bounded request.

## Smaller diagnostics, and CI that retries a platform cancellation

`cache_diagnostics` stored a 64-character digest per prefix message — about 8.8 KB on every request, roughly 470 MB in one workspace's ledger — to compare adjacent messages. It now keeps 16 hex characters (64 bits), which answers the same question.

A `macos-15` job that queued and was cancelled without a runner blocked CI and a release three times in one day. A cancelled push run on a long-lived branch is now re-run automatically, up to two extra attempts; pull-request runs are excluded, because their older attempt is cancelled on purpose.
