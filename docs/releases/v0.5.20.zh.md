# miao v0.5.20

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.20.md)

v0.5.20 改变会话写文件的位置：新会话留在你启动它的项目目录；工作树隔离变成显式操作且使用真实分支；提问会等待操作者，而不再一分钟就过期。

## 会话就在你启动的目录里

从 0.5.0 起，第一个会话独占检出，其余会话在 `.miao-worktrees/<id>` 的 detached 工作树里：没有分支，也没有回去的路。生成的文档因此落在操作者根本不会打开的目录。被报告的 `embrix` 案例里，规格只存在于某个工作树和 `main` 上，而检出停在另一个分支。

Claude Code 的本地会话就在工作目录里，工作树是显式选择。miao 现在也一样：

- 新会话在启动它的检出里开始；多个会话可以共用该检出。已有另一个会话在用同一检出时，TUI 会提示。
- 已经记录在工作树里的旧会话保留原 root。`miao worktree list` 能看到这些路径；把 `miao/<name>` 合回，或新开一个本地会话。

## 隔离是显式且带真实分支的

`worktree_enter` 把会话迁到 `.miao-worktrees/<name>`，检出真实分支 `miao/<name>`。提交可达、可 review、可 merge，不再是 detached。

- 删除工作树时按它实际持有的分支删除；`miao worktree remove` 的计划也按该分支计算。
- 工作树被外部删除时，先 `git worktree prune`，再优先在原分支重建；detached 只是兜底。
- 打开隔离会话时，TUI 会显示真实 root。

## 提问会等待

`question` 不再 60 秒过期。它会等到操作者回答或拒绝，与 Claude Code 可以无限期挂起的回调一致。无头调用仍可显式设置 `timeout_ms`，上限七天。例行的“engine restarted”提示也不再覆盖导致重启的“stored the key”提示。

## 验证

- miao-engine 654 个 lib 测试、工作树隔离 5、question 7、worktree 模块 7、CLI worktree 3、miao-tui 868 个 lib 测试、accuracy 4；clippy 无告警。
- 不升 schema：已有 ledger 无需迁移，其它打开的窗口也不会阻塞升级。
