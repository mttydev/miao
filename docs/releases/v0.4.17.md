# miao v0.4.17

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.17.zh.md)

v0.4.17 makes command output from Windows hosts readable. Chinese text that a
Windows console program printed arrived as a run of replacement characters,
because the engine decoded those bytes as if they were UTF-8.

## GBK output is decoded instead of flattened

Windows console programs write CP936 whenever the console code page is the CJK
default, and `cmd` and PowerShell keep that code page over SSH too — a non-CJK
system locale does not change it. The engine read every command's output with
`from_utf8_lossy`, which turns each Chinese byte pair into U+FFFD:

```
$ ssh build-host 'reg query "HKLM\SOFTWARE\OpenSSH" /v Nope'
����: ϵͳ�Ҳ���ָ����ע������ֵ��
```

Those bytes were always the message `错误: 系统找不到指定的注册表项或值。`; only
the decoding was wrong, so the text was recoverable rather than lost.

Output now decodes in three steps:

- Valid UTF-8 is returned byte for byte, so anything that already speaks UTF-8
  behaves exactly as before.
- Otherwise the bytes are decoded strictly as GB18030, a strict superset of GBK,
  tolerating a final incomplete sequence so a 32 KiB cap or a read boundary does
  not poison the buffer.
- Anything that is not recognizably text keeps the old lossy behavior.

The binary guard matters here. A strict GB18030 decode is already strong
evidence, but short accidental decodes exist, and the PNG file magic is the
trap: `89 50 4e 47` begins with a valid GBK pair that spells a Han character, so
a single-character rule read a file header as text. Text must therefore contain
two distinct CJK characters. Measured false-accept rates on random buffers are
0.005% at 64 bytes and 0% at 256 bytes, 2 KiB and 8 KiB; PNG, gzip and zip
headers stayed binary at 16 bytes, 64 bytes and 2 KiB.

The same decoder backs the live output a running background job reports and the
terminal read path. A pipe chunk can end in the middle of a multi-byte
character, so a reader reports only the complete prefix and carries the partial
tail into its next chunk instead of emitting a replacement character at the
boundary.

Characters that CP936 carries but that are not CJK — `℃`, `α`, `№`, box drawing
— are ordinary message content once CJK anchors the buffer, so they pass
through unchanged.
