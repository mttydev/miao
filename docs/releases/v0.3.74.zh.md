# miao v0.3.74

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.74.md)

v0.3.74 让模型知道自己身处何处——时钟、工作区知识索引，以及哪段文字才算指令；同时修掉 0.3.73 留下的两个 TUI 回归。

## 系统提示写明「什么才算指令」 (#3044)

固定的 `<instruction-authority>` 块现在指明仅有的三条指令通道，并把工具观察到的一切都当作数据：抓取内容里自称的「已批准」不等于批准，收到一份清单只授权阅读它、不授权执行其中条目。基础提示新增：优先广度优先检索而不是猜、条件编辑成功后不再重读、无人值守时的降级策略、材料不存在时推迟加载技能、任务清单的最后一项改为独立复核——高风险改动由一个全新的子任务评定。该块在 `source_budget` 中预留额度，64 KiB 上限依旧成立。

## 系统提示带上时钟与知识索引 (#3047)

模型此前既没有时钟，也看不到知识库，除非它想起来去列一次。现在两者都随系统提示提供：一个带本地日期的会话时钟块，以及一份有界的工作区知识索引，走与指令来源相同的授权路径读取。作为系统文本，它让相邻的 provider 轮次保持字节稳定——这正是 `prefix_stability` 守护的性质——并只在跨日或知识库写入时重建上下文 epoch，两种情况都有界；策略拒绝该知识库、或知识库为空/不可读时不产出任何内容。

## 侧栏占满窗口整个高度 (#3048)

0.3.73 把队列行、输入框与状态行收进了正文列，但仍然按整帧宽度布局。于是侧栏只画到输入带开始处：分隔线在输入框上方悬空收尾，输入框看起来只覆盖了屏幕左侧。

现在先做横向分栏（作用于整帧），正文列再自带一套纵向布局。侧栏从第一行贯到最末一行，分隔线到底；嵌套布局量出的宽度与输入框实际绘制的宽度完全一致。

## 撤销后的图片不再复用编号 (#3049)

粘贴图片、撤销草稿、再粘贴，会得到第二个 `[Image 2]` 标记和第二个 `image-2.png` 文件，之后输入框就再也打不进去了。原因有两个：编号取自「现存图片附件数」；而 `undo`、`redo` 与选区删除只改文本、不动附件表——于是离开草稿的图片把编号让给了下一次粘贴，字节继续挂在一个屏幕上已不存在的标记后面。

现在图片编号每个草稿只发放一次且只向前走；文件附件不占用图片编号。每个附件记录自己被画成哪个标记，每次按键处理后两张表对齐，被撤销的一步会连带丢弃提示本会继续发送的字节。被引擎拒绝的提示恢复时，图片也会完整回来。

## nix 构建能看到桌面工作区 (#3043)

根清单把 `apps/desktop` 声明为工作区，但派生式的 fileset 只带了 `packages`，于是 `bun install` 以 `Workspace not found "apps/desktop"` 失败，四个 `nix-hashes` job 都在算哈希前就挂了。现在 fileset 带上该工作区，配套的哈希更新一并落地。
