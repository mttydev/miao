# miao v0.4.1

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.1.zh.md)

v0.4.1 finishes the image-input and language feedback: pasted pictures reach Volcengine's DeepSeek on every route, a dropped image now says why, and on macOS the TUI answers in the system language even when the shell states none.

## Images reach Volcengine's DeepSeek on every route

The shipped catalog marks the dated id `volcengine/deepseek-v4-1-flash-261017` text-only, while Ark accepts an `image_url` part for it and describes the picture (checked against the live endpoint) — so routes built from the catalog snapshot replaced pasted images with the "model does not support image input" marker. The self-maintained overlay that corrects the modality now applies in the engine's own snapshot reader, covering stored-credential routes and the model picker manifest, with the same field-wise merge and `MIAO_MODELS_PATH` exact-catalog rules as the TS side (#3240, #3243). Declaring `capabilities.input` per model in `providers` config remains the contract for custom providers, now documented with a vision-model example (#3241).

## A dropped image says why

When a route's declared input modalities exclude image, the omission marker the model receives no longer reads as if the picture had been delivered: it instructs the model to tell the operator, and names the configuration fix (#3241).

## macOS answers in the system language

Shells on macOS often state no language at all (`LANG=C.UTF-8`), and the TUI used to answer English in that case. It now falls back to the system's preferred language when the environment is uninformative (#3238).
