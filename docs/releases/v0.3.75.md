# miao v0.3.75

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.75.zh.md)

v0.3.75 manages Sessions from the desktop window, makes switching provider accounts land on a model the account actually serves, and closes the paste-image wedge that could wedge the composer.

## The desktop window manages Sessions (#3051)

Pin, archive, rename and delete Sessions through the engine's catalog commands, with pinned rows grouped first and the list filtered by title. The rename uses an in-app dialog instead of `window.prompt`. A refused send keeps the draft, the error banner can be dismissed, messages are copyable, `Cmd/Ctrl+N` starts a new Session, and a sidecar that fails to start shows a retry instead of a blank window. The app also uses the design tokens it defines.

## Switching accounts lands on a model the account serves (#3055)

Switching an account in the keys dialog failed with `no registered account route for the selected model` whenever the new key did not serve the model the session was running — the common case, because a second key of one provider usually serves different models. The switch now tries two passes: first the route that keeps the session's model under the new account (refusing only when that route cannot host the pinned variant), then the account's own first route — the switch moves the model, which is what "use my other key" means. An unknown credential still fails, now naming the fix. The keys dialog also marks the account the session is pinned to, and a successful switch says what the next prompt runs.

## A late clipboard landing fills the marker the draft shows (#3056)

Pasting a screenshot and hitting enter before the clipboard read finished held the prompt and restored the draft — and when the read landed, the composer inserted a second `[Image N]` marker at the cursor. The draft then showed two markers for one picture, the next submit held again, and the composer never cleared. A clipboard image landing on a draft that already shows an unmatched `[Image N]` marker now fills that marker (the bytes take its number and its name) instead of inserting at the cursor, so the held prompt resubmits with exactly one marker per picture.
