# miao v0.4.15

v0.4.15 让页面重新落在窗格自己的底色上。在把窗格画成卡片的终端里，转录现在会采用宿主播报的卡片色，页面与它四周的内边距因此成为同一块表面，而不是在一块底色里浮着一个略小的矩形。

## 页面重新与窗格对齐

0.4.13 采纳了 `MTTY_TERM_BG`，也就是终端为窗格背后与四周卡片播报的颜色；0.4.14 把它回滚了，理由是页面应保留主题自己的 `#2e3440` 底色。对内边距的窗格来说这个判断是错的：宿主把卡片和它的内边距画成 `#1c1c1e`，只有内部单元格属于页面，于是把页面画成 `#2e3440` 就等于给页面套了一圈宿主的颜色。

在同一个窗口上实测，回滚前后对比：

| 区域 | 0.4.13（采纳） | 0.4.14（回滚） |
| --- | --- | --- |
| 窗口边框 / 左侧栏 | `#2e3440` | `#2e3440` |
| 窗格卡片 + 内边距 | `#1c1c1e` | `#1c1c1e` |
| miao 页面 | `#1c1c1e` | `#2e3440` |

宿主一侧从未移动，移动的只有页面。采纳播报色，才是消除接缝的那一步。

这次的采纳比 0.4.13 更进一步：播报色会写进主题目录里的每一个主题，而不只是当前可见的那个。主题选择器是靠换入目录里的调色板来预览每一行的，若目录里仍各留自己的底色，光标每扫过一行就会重新露出接缝。半透明主题保留自己（reset）的底色，因为宿主本来就从它透出来；落在明暗分界另一侧的宿主色仍然拒绝采纳，以免固定模式下的文字失去对比。

主题文件本身没有任何改动。采纳是运行期的决定：普通终端不会播报，因而完全保持原来的调色板；而改主题里的 background 常量，反而会把 mtty 的卡片色涂到其他所有终端上。
