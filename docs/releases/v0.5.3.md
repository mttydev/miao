# miao v0.5.3

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.3.zh.md)

v0.5.3 is about how the terminal answers you: a prompt shows the moment you
send it, the Session list no longer holds a turn, and a step that waits on you
asks for the answer instead of leaving the Session looking stuck. It also stops
the catalog from scanning message history on a cold start.

## The prompt shows when you send it

The transcript only learned of a prompt from a projection that already carried
it as a message, so Enter showed nothing until the engine had admitted and
promoted the input. On a 4.3 GB store the first message of the last forty new
Sessions landed 0.7–1.3 s after the Session row, and one whose prompt queued
behind a cold Session list waited 6.1 s.

The composer now puts the prompt in the band above the input the moment Enter
sends it, under the id it will be admitted as. The projection that lists the
input as pending, or carries the promoted message, replaces the echo — so the
text never shows twice and never blinks. A cancelled or refused input leaves at
once.

## The list no longer holds the turn

The Session catalog is one read of the whole store, seconds while the cache is
cold, and both request loops served one request at a time: a prompt queued
behind the list waited for the whole read, and naming a first prompt paid a
second read inline.

The engine now answers `session_catalog` from its own task, so its stdio loop
keeps serving requests and polling events meanwhile, and waits for in-flight
reads before it closes the stream. The TUI reads the list in the background on
a cloned client; reads that finish out of order are discarded so only the
newest publishes.

## A blocked step asks, and says how to continue

A step the checklist held for the owner used to end the turn with a note while
the empty composer kept rotating an unrelated example; the state read as a
stuck Session.

- The default prompt (the fallback for models without a family prompt) now
  requires a step that needs the owner's decision, an action only they can
  take, or access the agent lacks to be a `question` with concrete options —
  including "already done, continue" — answered in the same run.
- The held-work row ends with `reply to continue` / `回复继续`.
- The empty composer says `Reply to continue…` / `回复以继续…` while a wait or
  a block holds the list, instead of offering an example.
- A blocked item is announced once per item, and only to a window that is not
  focused.

## One line per Session, kept when it commits

The catalog's preview scanned the newest twenty messages of every Session:
4.63 MB of content for forty Sessions, ~116 KB each, which is what a cold
opening of the list paid for.

`engine_preview` now keeps one line per Session, written when the text that
earns it commits (a tool-only turn leaves it alone). Revert and unrevert
rewrite it from the messages still visible.

**Upgrade note:** the schema moves to 28. The first launch after upgrading
fills the preview for each existing Session once — a second or two on a 4 GB
store — and the list no longer scans message history afterwards.

## Smaller fixes

- The title bar reads `.git/HEAD` instead of spawning `git rev-parse` before
  the first frame.
- An Anthropic reply that ends with a stop reason this build does not know now
  finishes the turn instead of failing after its content arrived; a stream that
  names no reason, or that left tool calls in it, still errors.
- The Session list loads after the model catalog, so a plain launch names a
  model before the list is read.
- The caret is hidden while a frame is painted, so it cannot flash at the old
  position.
- Images are offered to every model; a model that refuses them degrades with
  its own message instead of the prompt being withheld.
- Leaving the terminal restores the state the shell inherits on exit.
