# miao v0.5.8

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.8.zh.md)

v0.5.8 changes what a Session may read by default, and restores the configured
references that grant reads outside the workspace.

## Reads follow the OS user by default

`read_file`, `read_image`, `list_files`, `glob` and `grep` were pinned to the
Session root: a path outside it was refused as outside the workspace. Worktree
placement (#3360) puts concurrent Sessions in `.miao-worktrees/<session>`, so a
Session could no longer read even the checkout it came from, and every outside
path needed a grant first.

Reads now default to `readScope: "host"`: a Session reads whatever the OS user
can read, including another checkout. Writes keep their single owner — file
writes, `apply_patch`, the knowledge and memory stores, and a command's working
directory stay inside the workspace. `readScope: "workspace"` restores the old
jail (the workspace plus read-only references), and the refusal names that
switch instead of only stating the rule.

## Configured references reach the engine again

`references` in `miao.jsonc` is the list of read-only paths a Session may read
outside the workspace. It was parsed and shown by `miao debug config`, but the
engine's read scope stayed empty: the TypeScript host used to write the
`references.json` manifest the engine reads as `--references-config`, and it
retired in #2840 without a replacement in the native entry. With
`readScope: "workspace"` the key therefore granted nothing, and the system
context never listed the references.

The native entry now derives the manifest from the same layered documents the
engine reads. A relative path resolves against the directory of the document
that declared it, `~/` expands through the home directory, `hidden` entries and
paths that do not exist grant nothing, git repositories are reported and
skipped, and more than sixteen grants are truncated with a warning instead of
failing the engine's own limit. The legacy `reference` key still works. All
four entry points receive it — the TUI, `miao run`, `miao serve` and ACP — and
an explicit `MIAO_ENGINE_REFERENCES_CONFIG` still wins.

## Verification

- `cargo test --lib read_scope`, `tests/read_scope.rs`, and the tools,
  directory, references, context and config-reload suites in
  `crates/miao-engine`; `cargo clippy --all-targets -- -D warnings` and
  `rustfmt --check`.
- `cargo test` in `crates/miao-cli` (70 tests), the same clippy and format
  gates, on a Linux build host, plus CI on the pull requests.
- End to end on a macOS arm64 build: with the default `readScope`, reading a
  file outside the workspace succeeds and returns its content; with
  `readScope: "workspace"`, the same read is refused. A `miao serve` start
  with a configured reference writes the expected `references.json` manifest
  before the engine starts.

## Upgrading

The new default is a behaviour change: if a deployment relies on reads staying
inside the workspace, set `readScope: "workspace"` in its configuration.
Project configuration is still resolved from the launch workspace, not from a
per-Session worktree, so put `references` in the checkout's `.miao/` or in
`~/.config/miao/`.
