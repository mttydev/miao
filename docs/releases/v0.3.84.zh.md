# miao v0.3.84

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.84.md)

v0.3.84 让长会话的自动压缩真正可靠，并让流式回答不再把一句话拆成几段。

## 自动压缩不再一次慢尾巴就永久关停

一次压缩会把历史按分段逐段总结。当后面某一段超时、或返回了引擎无法使用的文本，这次失败会计入“三次失败就关掉该会话自动压缩”的闸门，已经总结好的那些段也随之作废。长历史里连着三次运气不好，就足以永久关掉自动压缩，之后窗口一路填满，直到所有请求都被拒绝。

现在，只要一趟压缩成功总结过至少一段，就不再计入那个闸门：这次尝试以 partial 上报，下一轮的压缩会重新尝试这段历史。完全没有任何产出的那趟仍然计数，所以确实无法总结的 provider 会停下来而不是空转。闸门本身也是半开的——历史比失败时增长了一成、或经过四个已结算轮次之后，会再放行一次尝试，于是被修好的 provider 无需手动 `/compact` 也会重新用上。

## 对话里能看到压缩切在哪里

压缩过的会话以前看起来就像更早的对话凭空消失了。现在切点处会打印 `── conversation compacted · earlier turns summarized (N chars) ──`，模型还能看到什么、看不到什么，一眼可辨。

## 流式回答保持一段就是一段

有的网关会把 thinking 插在回答中间：先吐一两个字，再吐一段思考，然后继续这句话。每次切换都会新开一个段落，于是回答把那几个字单独画成一个 bullet，句子在 `Thinking` 标题下面另起一段——看起来就是文字被“一两个字”截断了好几行。现在句子中途到达的思考会并到它打断的那段之上，prose 继续写在同一个块里。

## 本次发布还包括

- **推理强度跟随提示词**：开启 `auto_effort` 后，明确要求多思考或少思考的提示词会选中对应的已注册强度，而不是继续沿用会话上次固定的那个。
- **下一条提示建议**：开启 `predict_next` 后，空闲会话会给出可直接用 `Tab` 接受的一行建议。
- **版本号滚动进位**：`bun script/set-version.ts --bump patch|minor|major` 直接推导下一个版本，patch 号不会再到达 100。
- **被中断的一轮会收尾工具调用**：被打断的一轮里从未执行的工具调用现在读作已结束，而不是永远转圈。
