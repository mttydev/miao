# miao v0.4.15

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.15.zh.md)

v0.4.15 puts the page back on the pane's ground. Inside a terminal that draws
its panes as cards, the transcript now adopts the card colour the host
announces, so the page and the padding around it read as one surface instead of
a slightly smaller rectangle floating inside another.

## The page meets its pane again

0.4.13 adopted `MTTY_TERM_BG` — the colour a terminal announces for the card
behind and around a pane — and 0.4.14 reverted it, on the reading that the page
should keep the theme's own `#2e3440` ground. That reading was wrong for a
padded pane: the host paints the card and its padding `#1c1c1e` and only the
inner cells belong to the page, so painting the page `#2e3440` leaves a ring of
the host's colour around it.

Measured on one window, before and after the revert:

| band | 0.4.13 (adopted) | 0.4.14 (reverted) |
| --- | --- | --- |
| window chrome / sidebar | `#2e3440` | `#2e3440` |
| pane card + padding | `#1c1c1e` | `#1c1c1e` |
| miao page | `#1c1c1e` | `#2e3440` |

The host side never moved; only the page did. Adopting the announced colour is
what removes the seam.

The adoption now goes further than 0.4.13 did: the announced colour lands on
every theme in the catalog, not only the visible one. The theme picker previews
rows by swapping a catalog palette in, so a catalog still holding each theme's
own ground reopened the seam on every row the cursor crossed. Translucent
themes keep their own (reset) ground since the host already shows through them,
and a host colour on the far side of the light/dark divide is still refused so
pinned text stays readable.

Nothing in the theme files changed. Adopting the colour is a runtime decision —
a plain terminal announces nothing and keeps exactly the palette it had, and
editing a theme's background constant would have painted mtty's card colour over
every other terminal instead.
