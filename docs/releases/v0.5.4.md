# miao v0.5.4

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.4.zh.md)

v0.5.4 makes the transcript easier to read and stops it from claiming things
that are no longer true: a prompt is recognisable at a glance, a finished job
no longer goes on naming itself, and an image the provider would reject is
fitted before it is sent. It also makes the workspace boundary and a second
window's upgrade behave the way the message says.

## Your prompt is a block again

The operator's words were a bare line behind `❯`, so in a long conversation a
question looked like the prose around it. Each prompt now sits on a band of the
theme's panel tone: the renderer already pads a row with a background out to
the pane's edge, so the band is continuous across wrapped rows and reaches the
right column. It adds no rules and no padding rows, so a short question still
costs one row per line. The colour comes from the palette, and `NO_COLOR` drops
it entirely.

## A finished job stops naming itself

The input could show `waiting on 1 background job · 37m 12s · <command>` for a
job the engine had already marked completed; its clock kept counting because it
is recomputed from the cached start on every frame. The waiting line was
painted from cached job rows with no bound on their age, so once the reads
stopped reaching the window, the last `running` answer stayed up as if the job
were still moving.

Job rows now carry the time the engine answered, and rows older than ten poll
intervals are dropped before they can be painted. A running row on screen also
guarantees that its next read is scheduled, so a cached row can never outlive
its own last read. The engine's pause still keeps the reads coming, so a real
wait shows its details again as soon as the engine answers; a read that stays
silent now shows the plain pause state instead of a fabricated clock.

Two more ways a wait could outlive its job are closed here. A job whose owning
runtime is gone — most often an engine restart inside the same window — stayed
`running` in the journal forever, because its Session lease named the pid that
was still alive; recovery now reclaims a job unless a *different* live process
holds it, the way Session recovery already did. And the composer treats a row
as finished once it is past the deadline its caller declared, so a task that
lost its process cannot keep a clock running for a day.

## `/model` opens at once

The model picker is local, but the command used to wait for the engine's first
`model_catalog` answer before drawing anything. A cold start — store migration,
route materialization — put that round trip in the seconds, and the screen
looked frozen. The picker now opens immediately on the rows the window already
holds, or on a "loading models" row when it holds none, and the answer fills
the same dialog in place. A picker the operator closed stays closed.

## Images fit before the provider sees them

A session with many inline images could fail with
`image_dimensions_too_large` on every turn: history carried the original bytes,
and replaying them re-triggered the same deterministic 400. The engine now
fits the request copy to the provider's limits — at most 2000 px on the long
side and roughly 512 KB, with a JPEG quality ladder and a PNG attempt for
transparent images. Stored history is untouched, so an already-stuck session
recovers on its next turn, and that 400 is no longer replayed as if it were
transient. An image that cannot be measured or decoded is replaced by a short
note instead of being sent.

## The read boundary says what to do

`read_file` and `read_image` still refuse paths outside the workspace, but the
refusal now names the reachable scope: copy the file in, or read it through a
host-granted read-only reference. `read_file`'s description mentions that
scope, and `bash`, `run_command`, and `start_job` warn that files written
outside the workspace cannot be read back — a conversion into `/tmp` no longer
costs a turn on a refused read.

## A new window waits for the old one

Opening a window while an older miao process still held the store used to start
with no engine: the schema upgrade refuses to run while the store is in use,
and that refusal was reported as a start failure asking you to close the
windows first. The engine now treats that refusal as a wait, says once that
another miao window is using the workspace's storage, retries every two
seconds, and comes up by itself when the other window closes.

## Smaller fixes

- The prompt band keeps its theme relation when the host's page colour is
  adopted, and keeps no invisible padding under `NO_COLOR`.
- The workspace-boundary hints also cover `run_command` and `start_job`, so the
  description matches the refusal.
