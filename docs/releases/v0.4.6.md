# miao v0.4.6

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.6.zh.md)

v0.4.6 makes the first start an onboarding instead of a refusal, and keeps a committed answer on screen when you are reading back through the conversation.

## A first start has somewhere to begin

A start with nothing configured used to fail with `--model is required`. It now comes up and serves the catalogs the picker drives: every provider the install ships is listed as needing auth, the model list is empty, and a prompt answers with the same guidance the startup error carried — store a key, then pick a model (#3269).

Storing that first key is enough. The engine derives routes from the configuration and the credential store, and an engine that is already running re-derives them on `config_reload` instead of needing a restart. The TUI's embedded engine now takes that path and re-reads both catalogs, so the key stored from inside the conversation appears in the picker immediately. A host-written route manifest keeps its old contract: its primary route still has to match the provider the host launched with.

## A committed answer stays on screen

Scrolling back through history is a reading position, not a pause. When a reply finished while the reader was in history, the committed projection was withheld and the draft it replaced had already been cleared, leaving the conversation blank until End was pressed. Fresh projections that only append — the answer, the next prompt — now paint immediately; only a refresh that would drop entries already loaded is held (#3268).

The scroll clamp also moved out of the projection step and into the frame that has the wrapped rows in hand, so a viewport no longer snaps back to an old tail because an unwrapped frame undercounted its lines.

## Compatibility

Configured starts resolve exactly as before. Unmodeled starts are new behavior: the engine, not a missing flag, decides what a first run has to offer.

## Maintenance and verification

CI covers `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, the engine and TUI test suites, and the new `unmodeled_serve` integration cases: an empty start serves both catalogs, a stored key becomes a served route, and a key stored while the engine runs becomes a route on `config_reload`. Locally the full engine (588) and TUI (766) library suites pass on Rust 1.100 stable.
