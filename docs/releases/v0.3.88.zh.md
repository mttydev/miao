# miao v0.3.88

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.88.md)

v0.3.88 让"目标还开着"时回合不能靠一段纯文本收尾，并去掉了两处名不副实的标签与记录。

## 目标仍 active 时，纯文本回合不算结束

模型把已批准的指令答成一份计划、又不调用任何工具，就等于结束了这一轮：引擎看到纯文本回合，没有东西继续它，操作者只好为自己已经要求过一次的每一步再输入一次。

引擎本来就有"配置了 verification 命令时不通过就不许结束"的判定。同一个边界现在也读 goal 的持久记录：只要 goal 是 `active`，第一次纯文本回合会续跑一次，点名目标并明确"一次做不完"不是阻塞；第二次则写入 `loop.stopped`（原因 `goal-open`）并让这一轮可见地结束。既有守卫保持不变——列表在等待外部事件时仍然 idle，重复无进展仍会暂停。

## 侧栏说的是它真正在数什么

Activity 那行打印的是 `interventions.*`——整个会话累计的批准、回答、拒绝、取消与改写——标签却写成 `needs you`，读起来像有一个待回答的问题，实际上没有可回答的地方。现在它写 `decisions`。

## 每回合少写一条日志

`instructions_loaded` 原本在每个 provider 回合都写一条，而读取方只取最新一条来得知某个 location 当前生效的 sources：在一个实际工作区里就有 47,299 条。现在只有在 `location` 或 `sources` 真的变化时才写，比较在同一个事务内完成。
