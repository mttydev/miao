# miao v0.3.85

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.85.md)

v0.3.85 让内置代码索引在模型需要之前就准备好，让工作树复用主检出的索引，并把索引的覆盖范围写进回答。

## 第一次提问之前，索引已经预热

引擎以前只在工具调用到来时才打开代码索引。工作区上的第一次 `codegraph_explore` 因此要在这一轮里承担建库成本：每轮最多遍历 1500 个文件或 4 秒，用这一片结果回答并附上“仍在构建”，剩下的留给后续调用。大仓库上的第一次回答是不完整的；如果会话一直没调用这个工具，索引就根本不会建。

现在 Runtime 一旦知道引擎私有 store 的位置，就在后台开始构建当前工作区的索引。同一索引文件只启动一个预热任务，重复构造 Runtime 不会重复建库。`codegraph_explore`、`codegraph_node`、`codegraph_callers` 会等待索引完成后才回答；如果超过 `MIAO_CODEGRAPH_WAIT_MS`（默认 120 秒）仍未完成，调用会明确返回“索引仍在构建”的错误，而不是半成品。`codegraph_status` 仍保持有界刷新，用来观察构建进度。

## 工作树从主检出起步

链接工作树是另一个目录，以前会得到另一个空索引，并把整个仓库重新抽取一遍。现在工作树第一次被索引时，先从主检出的索引复制一份，再按工作树的文件增量刷新。未修改的文件保留原有行，只抽取分支改过的文件。索引文件仍归工作树自己所有，播种不会写回主检出的索引。

## 回答会说明覆盖范围

每个 codegraph 回答现在都会写明检索的是哪个工作区，并说明其他检出没有被索引。查询里出现工作区之外的路径会明确警告；工作区没有任何已索引源文件时也会直接说明，而不是返回一个空符号列表。这样，跨仓库提问的失败方式会变得可见，而不像是一个来自错误仓库的完整答案。
