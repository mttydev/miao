# miao v0.3.75

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.75.md)

v0.3.75 让桌面窗口可以直接管理会话；切换 provider 账号会落到该账号真正可用的模型上；粘贴截图把输入框卡死的问题关闭。

## 桌面窗口穿上了产品的主题 (#3058)

渲染器此前从未挂载主题 Provider，所有 v2 设计 token 都解析为未定义变量，窗口以无样式的黑字白底呈现。入口现在挂载 `ThemeProvider`，界面用 token 与共享的 v2 图标集重做：品牌行、强调色的新任务按钮、搜索框、带置顶标记的分组侧栏、带输入卡片与建议 chips 的欢迎页、聊天气泡、工具 chips、带发送/停止图标的胶囊输入框，以及完成主题化的对话框。macOS 红绿灯让出标题栏，顶部条作为拖拽区域，欢迎页覆盖无会话状态，应用包内的字体经由 `publicDir` 解析。

## 桌面窗口可以管理会话了 (#3051)

通过引擎的 catalog 命令置顶、归档、重命名与删除会话，置顶行排在最前，列表按标题过滤。重命名改为应用内对话框，不再用 `window.prompt`。发送被拒绝时保留草稿，错误横幅可以关闭，消息支持复制，`Cmd/Ctrl+N` 新建会话，sidecar 启动失败时显示重试而不是空白窗口。应用同时改用自己定义的设计 token。

## 切换账号会落到该账号可用的模型 (#3055)

在钥匙对话框里切换账号时，只要新钥匙不提供当前会话正在跑的模型，就会以 `no registered account route for the selected model` 失败——而这恰恰是常态，因为同一 provider 的第二把钥匙往往服务不同模型。现在切换按两轮匹配：先找在该账号下保持当前模型的路由（仅当该路由无法承载固定的 variant 时才拒绝）；找不到就落到该账号自己的第一条路由——切换会带动模型，这正是「换我的另一把钥匙」的本意。未知凭据仍然失败，但提示会写明补救步骤。钥匙列表同时标出当前会话固定的账号，切换成功后会说明下一条 prompt 使用什么模型。

## 迟到的剪贴板读取会补齐草稿里已有的标记 (#3056)

粘贴截图后在剪贴板读取完成前按下回车，提示会被暂存并恢复草稿——而读取落地时，输入框又在光标处插入第二个 `[Image N]` 标记。草稿于是为同一张图显示两个标记，下一次提交再次进入暂存，输入框永远清不掉。现在剪贴板图片落地时，若草稿里已经存在没有对应字节的 `[Image N]` 标记，就直接补齐它（字节采用它的编号与文件名），而不是在光标处再插一个；被暂存的提示会带着「一个标记一张图」重新提交。
