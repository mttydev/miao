# miao v0.3.73

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.73.zh.md)

v0.3.73 makes `/clear` mean what it says, arms automatic compaction where a request can actually reach, and keeps the footer out of the sidebar.

## `/clear` clears everywhere (#3035, #3036)

The engine never deleted anything: `/clear` checkpoints the history with an empty summary so the next provider prefix starts fresh, and keeps every row for audit. Both clients ignored that checkpoint. The TUI blanked its pane and then rebuilt the whole transcript from the snapshot on the next re-projection — a transport resync, a quiet-frames recovery — so cleared turns came back a while later; the sidebar's context row kept the occupancy of the conversation that had just been dropped; and the desktop window attached its event stream at sequence zero, so reopening a cleared Session replayed all of it while the header kept counting the messages.

The TUI's projection now starts after a clear checkpoint and seeds the transcript's tail there, so a failure recorded before the cut no longer trails an empty pane; `usage_report` reports zero occupancy once the clear is newer than the last turn, and `ContextCleared` asks for it again. The desktop reads the cut from the snapshot and attaches after it, counts the messages that survive it, and keeps the conversation screen instead of falling back to the first-run welcome.

## Automatic compaction arms where a request can reach (#3034, #3038)

A session sat at 654K tokens with a 922K threshold while the same conversation was painted against a 655K ceiling. Both figures were correct for the inputs they were given: a request can only send the model's window minus the output it must reserve (a deepseek route declares 393,216), and an undeclared capacity was read as "reserve nothing". `input_ceiling()` resolves that reserve in one place — a declared capacity is honoured, an undeclared one falls back to a quarter of the window, and nothing may reserve more than half — so the trigger and the painted percentage read the same number.

Arming is not enough when the pass cannot finish. Every summarizer call had a flat 20 s deadline while one call carries up to a few hundred thousand tokens: the deadline expired, the pass reported `summary timeout`, gate ⑤ counted it, and after three the Session was told automatic compaction was paused — in exactly the situation the shrink exists for. The budget now follows the text a call reads: a second per 5000 characters, floored at 20 s and capped at five minutes, shared by the prefix attempt, each segment and the truncated-body retry. `Budget::threshold` also keeps the trigger reachable on a small window, and a Session whose window nothing states now says so once and records `compaction.disabled` (reason, model, fix) instead of failing silently.

## Shell actions on Windows ask instead of settling themselves (#3037)

`product_permission` classified a shell action by parsing the command with Unix shell semantics: `git status` parses as safe, but the command line that actually runs on Windows (cmd or PowerShell quoting, builtins, drive-relative paths) is not the thing that was parsed, so a readonly bash action was allowed where the policy expected an ask. The bash arm is now unix-only; on Windows a shell action asks. The edit arm is unchanged — it is a path check, and a protected `.env` edit already asks.

## Windows names and paths in one spelling (#3030, #3031, #3033)

Three Windows-only mismatches, all of them the verbatim prefix (`//?/C:/…`) meeting a plain path:

- `@reference` carried the prefix, so a policy written `@reference/**` met a `?` segment and never matched — a denied instruction file still reached the system context and a per-file skill policy was ignored. #3033 gives the name its separator, #3030 strips the prefix when the resource is named.
- The product permission classifier compared the requested resource with the host directory through `strip_prefix` on the raw spellings, so a resource plainly inside the workspace was classified as outside it — in auto mode that turned a protected `.env` edit into an auto-allowed one. Both sides now go through the tool layer's `canonical_plain` (#3031).
- The formatter fixture wrote with `cmd /d /s /c` and a quoted redirect target; `/s` re-parses that line, the write landed elsewhere and the formatter reported `failed`. It writes with PowerShell and a literal path instead (#3030).

## A monitor's finish notice is never refused (#3028)

A finished job's steer notice was admitted under the fixed id `monitor:<job>:finished`, while its text changes between deliveries — the notice becomes some, the state snapshot moves. A reused id is only an exact retry when everything matches, so the second delivery raised `input id conflicts with an existing admission` and was recorded as `monitor.notice_failed`. The finish admission now appends a uuid, like the per-notice admission above it, so a repeated delivery is a second message rather than a refused one.

## TUI details (#3032, #3039, #3040)

- The sidebar and `/context` each divided the occupancy by their own window; against the input ceiling the same conversation read 52% in one place and over 100% in the other. One helper answers for both surfaces and clamps at 100, so an overflowed ceiling reads as full rather than 131% full. Pasted screenshots also stopped sharing one file name: each is named after the marker it shows (`image-1.png`, `image-2.jpg`) (#3032).
- A clipboard result that arrived while the event queue was full was coalesced away — and since that event is what clears the clipboard-read flag, Ctrl+V, Alt+V and `/paste` went silently dead for the rest of the session. Clipboard results are now delivered regardless of queue pressure (#3039).
- The queue rows, the input box and the status strip were laid out at the window's width while only the body was split, so a long queued prompt and the build at the row's right edge ran under the sidebar. All three now stop at the conversation column's rule, and the band's background still covers the whole row (#3040).
