# miao v0.3.89

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.89.zh.md)

v0.3.89 makes the Session say what it is doing when it stops, refuses an evasive block, and stops re-reading its own repeated conclusions.

## A stop is visible, and an evasive block is refused

A drain ends for a reason — a blocked item, a list that did not move, a goal still open — and the engine already recorded it. The transcript ignored the record, so a stopped Session looked exactly like an idle one: `loop.stopped` now reaches the conversation as an `engine` row (`paused: blocked · <item>`, `paused: goal-open`), deduplicated by sequence and cleared by the next continuation.

A `blocked` goal is now a claim that must name something the model cannot change: hardware down, power off, offline, a credential or approval a human holds, a third party that is unavailable. "Too large for one reply", "too complex", "needs many steps" are refused at the write surface, because honouring them parks a Session the operator already approved. The engine's own pauses carry a `loop: ` prefix and stay exempt.

## A repeated conclusion is not fed back

A model that closes one turn with a conclusion and opens the next with the same words states one fact twice, and the copy it reads back teaches it to keep doing so. The request copy now drops an assistant message that repeats the reply immediately before it. A message carrying a tool call is never dropped, and a user turn or a tool result ends the comparison, so the same words either side of real work are two answers, not an echo. The durable transcript keeps every row.

## Fewer trims, fewer phantom waits

`context.trimmed` was written 11,306 times across 2,115 turns because the trim stopped as soon as the request fit: the history sat one message under the limit and the next tool result put it back over. It now trims to nine tenths of the budget, so one trim covers several steps.

A long but normal wait is also no longer indistinguishable from a stall: past ninety seconds the strip says `still inside the provider window · Esc interrupts`, which is true before any request-size allowance.

## The sidebar says what it counts

The checklist header reads `TODO done n/m` once every item is completed, instead of `TODO n/m` beside a new instruction. (The `decisions` rename and the context-selection dedupe shipped in 0.3.88.)
