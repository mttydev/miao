# miao v0.5.18

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.18.md)

v0.5.18 是一个修复版本：Esc 中断当前轮次后，排在它后面的输入会真正送达模型。

## Esc 只停屏幕上显示的那一轮

大 ledger 会让画面滞后：一个被报告的会话，其 ledger 每次写事务要 10–16 秒，负责撤下已结束 run 的投影会晚到几分钟，期间排队带一直画着卡顿期间输入的提示。

此前的 Esc 会取消“请求落地时”正在运行的 run。此时被中断的轮次已经结束，接力的 drain 正带着排队输入启动，于是 Esc 把它也取消了，模型根本没看到那条消息，看起来就是“排队没进去”。

现在 Esc 会带上屏幕显示的那个 run id。引擎只在该 run 仍然活动时接受取消；过期的 id 会被忽略，因此正在投递排队输入的接力 run 会继续运行。日志里的来源记为 `operator`，取回排队输入仍然记 `take_back`。

## 排队带跟随投影收敛

提交后、引擎接收前，输入会先在排队带里显示为本地回显。此前只有 `input.promoted` 事件能撤下回显；如果某次投影的 pending 列表里已经没有它，回显反而会被保留，因为“不在 pending”与“快照还没看到这次 admission”看起来一样。事件迟到或丢失时，已经进入对话的提示就会一直显示为排队。

现在每个回显记录 admission 落下的序号。当快照的 cursor 已经覆盖该 admission、且输入不再处于 pending 时，回显随投影一起退场；画面滞后或重连后也不会继续显示已经送出的提示。

## 验证

- `guarded_cancel`：过期的执行 id 不会停掉接力 run；`operator` 与 `take_back` 来源分别落账。
- miao-tui 867 个 lib 测试，包含 Esc 携带屏上 run id、投影撤下已提升回显。
- miao-engine 651 个 lib 测试；两个 crate 的 clippy 均无告警。
