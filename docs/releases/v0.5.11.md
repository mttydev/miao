# miao v0.5.11

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.11.zh.md)

v0.5.11 is a patch for a queued prompt that stayed in the band after the engine had already promoted it.

## A queue that never drained

The band above the composer is not one list. It is the pending list from the last snapshot plus the echoes a prompt leaves locally until the engine settles it. On promotion the echo was kept until the next projection retired it — but that order is not guaranteed. The projection carrying the promoted message can arrive before the promotion event, and it drops the echo because the snapshot no longer names the input as pending. Nothing recomputed the band afterwards, so the settled prompt stayed on screen, reading as a queue that never drains, until something else reopened the Session.

## Settlement removes both copies

An `InputSettled` event now drops the echo and the snapshot's own copy of that input id, together with its pending prompt row, then recomputes the pending count and repaints the band in the same event — whichever of the projection and the event arrives first. Cancelling a queued prompt behaves as before: the band is recomputed at once.
