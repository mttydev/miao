# miao v0.4.19

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.19.zh.md)

v0.4.19 fixes the status line that kept naming a background job for hours after
it had finished, plus two smaller defects either side of it.

## A finished job stops being drawn as running

A Session could sit under `waiting on 1 background job · 2h 3m elapsed` while
every job it had ever started was terminal — the engine's own job table held
nothing but `completed`, `failed`, `cancelled` and `unknown`.

The rule behind the line was sound: it renders only while some cached row is
non-terminal, and the clock stops once every cached row is terminal. The defect
was one step earlier. The read that refreshes those rows swallowed its own
failure:

```rust
if let Ok(value) = client.request("jobs", …).await {
    …                                  // on failure: nothing is sent at all
}
```

A failed read therefore left the previous rows untouched. A stale `running` row
kept "something is running" true, which re-armed the poll every second, which
read again, which failed again — so a single failed read could pin the line for
the life of the process.

A read that does not answer is not the same answer as a list. The event now
carries `Option`, the failing path reports `None`, and `None` drops the cached
rows and stops the clock. The line exists to say whether a job is still moving;
a row this Session can no longer observe is not evidence that it is.

## Parallel tool results reach Anthropic as one turn

When a turn ran several tools at once, their `tool_result` blocks reached the
Anthropic API as a user message immediately following the previous user message.
The API expects those blocks to open the next user message and only that one, so
the request shape was wrong. Consecutive user turns are now merged, and media
inside a result stays inside it.

## A non-ASCII cell no longer desynchronises the cursor

After a symbol wider than one cell, the inner backend's own cursor move could
start from the wrong column, leaving the prediction one cell off. Each run now
starts fresh after a non-ASCII symbol, which re-syncs at the true cell. The split
is on non-ASCII rather than on a width table's verdict, because the terminal — not
the table — decides how far the cursor actually moved.

## Also in this release

- **tui**: resync after non-ASCII cells (#3347)
