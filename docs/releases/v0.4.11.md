# miao v0.4.11

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.11.zh.md)

v0.4.11 makes automatic compaction fire where a route's input really ends, says why a compaction pass failed, and refreshes the default palette and tool-row spacing.

## Compaction arms where the input really ends

A declared `limit.output` is the model's maximum, not what a turn asks for. Some providers receive it (Anthropic requires `max_tokens`); OpenAI-compatible routes send no output cap at all. The trigger nevertheless subtracted the whole declaration from the window: a 1M route declaring `output: 393216` planned against 655,360 and compacted at 622,592 — 59% of the window the operator sees — even though the same endpoint accepted a 941,198-token request for that model.

Model routes now record whether their provider actually receives the declared cap. When it does, the declaration is still reserved whole. When it does not, the ceiling reserves a sixteenth of the window, enough for the server's own completion default. For the route above the trigger moves to 933,888 (89% of the window), still under the largest input the endpoint accepted. The request bound, the painted percentage and the summarizer capacity keep reading the same ceiling.

## A failed pass says why

An automatic compaction pass that the summarizer refused cleared the status phase in silence: the conversation simply stopped mid-history with nothing saying why compaction did not run, which reads exactly like a compaction that never started. The failure reason now lands in the composer notice as `Compaction failed · <reason>`, while the running row and phase still clear.

## A calmer default palette

The default theme was repainted so the canvas, panels and syntax hues agree with each other and with a dark terminal background. Light and dark variants share the same role names, and the code-block syntax assertions were updated with the palette.

## Tool rows sit on the page

A tinted band behind every call stacked the transcript into grey slabs, and two consecutive calls read as one crammed block. Every call now keeps the page background and is marked by its badge alone, with one blank row between calls so stacked panels stay distinct.

## A calmer diff and badge palette

Changed diff rows now sit on deep green and deep red bands, with the marker carrying the only strong hue. Line numbers and folded hunk headers read their own theme tokens instead of borrowing the muted text colour, and every tool label wears one filled badge instead of a per-category hue. Themes can declare `toolBadgeBg` / `toolBadgeFg`; the existing `diffLineNumber` / `diffHunkHeader` keys now actually drive the render.
