# miao v0.3.79

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.79.zh.md)

v0.3.79 teaches file snapshots to lean on git, and finishes wiring the workspace memory store into the engine: the model can save and recall facts, context carries them across compaction and restart, and an optional boundary pass extracts durable facts on its own.

## File snapshots prefer git (#3088)

The three-phase revert recorded every captured file as an engine-side blob, capped at 8 MiB — and a tracked file past that cap was recorded as unrestorable, so a files-phase revert deleted it outright. A capture now checks the repo: a touched path that is tracked and clean at HEAD records a `git:<sha>` reference instead of a blob, and restore materializes it with `git show` at any size. Dirty, untracked, and gitignored paths keep exact-content blobs, non-git workspaces behave exactly as before, and a git answer that fails or runs long falls back rather than blocking the capture. The repo head travels with every capture result.

## Sessions can remember (#3089)

The memory store gains its callers. `memory_save` persists a durable fact (duplicates rejected, 500-character cap); `memory_recall` lists active entries with a substring filter. The system context carries a bounded `<memory>` block read through the authorized path, so saved facts survive compaction and restart, and the block names the two tools.

Auto-extraction ships behind `memory.auto_extract`, off by default. When enabled, every N settled assistant replies (default 10) spawn a background pass that asks the model for durable facts, parses a lenient JSON array, caps and deduplicates the candidates, and appends unreviewed `auto: true` entries for the operator to review. The pass is never awaited — it cannot block or fail the turn — and rides the process stop token.

## A goal loop that only answers "waiting" stops (#3087)

A drain whose goal pass kept answering "waiting" armed itself again forever; the loop now stops instead of spinning the budget away.
