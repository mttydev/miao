# miao v0.5.15

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.15.zh.md)

v0.5.15 is a patch that lets two Sessions of one repository find each other again — and keeps stale screen text out of the exit command.

## Peers follow the project, not the worktree

Since 0.5.0 a second Session in one checkout is placed in its own `.miao-worktrees/<id>` tree, and the placement root is what `send_message`, `read_session_context` and `list_sessions` compared. Two Sessions of the same repository therefore saw no peers at all: each worktree read as its own project.

Project identity is now the checkout every worktree of a repository shares (`git rev-parse --git-common-dir`), recorded beside the placement when a Session is created. Startup backfills Sessions placed before the identity existed, and a directory outside a repository is its own project. Peer mail, the context reader, the Session list and the store's delivery boundary compare the project, with the placement root as the fallback until a row is backfilled.

## The exit banner can be copied again

The banner after quitting painted over rows the restored screen still held, so text beyond the shorter line survived beside it: a copied `miao -s` could read `ses_…19800e` for a Session whose id is `ses_…1980`. Every banner row now erases to its end and the block is written in one call.

## Verification

- worktree: a linked tree and its checkout answer one project.
- peers: mail lands between two worktrees of one project, another project is refused at the store boundary, and `list_sessions` names a peer in another worktree.
- 651 `miao-engine` lib tests, 865 `miao-tui` lib tests, 13 session-messaging tests and the TUI smoke suite pass; clippy is clean.
