# miao v0.5.14

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.14.zh.md)

v0.5.14 is a patch that puts the coding-plan meters back in the sidebar: the account the current model spends, one row per window, without delaying the first prompt.

## What the sidebar shows

`PLAN · QUOTA` now appears on the landing screen and in a Session for the model in use. Each window is one row: a bar, the percentage, the used/limit figures the plan is bought in, and the reset countdown. A narrow column drops the figures first and the countdown second, so nothing wraps.

- opencode-go: 5-hour, weekly and monthly
- Zhipu / Z.ai coding plans: 5-hour and weekly credits
- Command Code: 5-hour and weekly windows plus the monthly pool

Two logins on one provider stay separate, and switching models switches the block to that provider's account.

## Why it was missing

The TUI asked for the meter with a `{}` params object, but the engine's `Quota` command is a unit variant and rejected the call before it reached the collector. The block therefore never painted in any released build. A second problem made the first prompt feel queued: the collector fetched four provider endpoints inside the command loop, so a prompt admitted at the same moment waited behind them.

## What changed

- `quota` and `devices` are called without params.
- The meter answers from cache immediately (`pending` on a cold cache) and refreshes on a background task; the first prompt no longer waits behind provider calls.
- A failed endpoint is retried once, then that account's last answer is reused for up to fifteen minutes.
- Rows are scoped to the current model's provider and account, and each window occupies one line.

## Verification

- A PTY run of the built preview showed only the current `opencode-go` account with its 5-hour, weekly and monthly rows; the figures matched the account pages.
- 863 `miao-tui` tests and 650 `miao-engine` tests pass; clippy is clean on both crates.
