# miao v0.3.85

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.85.zh.md)

v0.3.85 makes the built-in code index ready before the model needs it, reuses a worktree's main index, and makes the index boundary explicit.

## The index is warm before the first question

The engine used to open the code index only when a tool call arrived. The first `codegraph_explore` on a workspace therefore paid the build cost inside the turn: it walked at most 1500 files or four seconds, answered from that slice with a "still building" note, and left the rest for later calls. On a large repository the first answer was partial, and in a session that never called the tool the index was never built at all.

A Runtime now starts building its workspace's index in the background as soon as it knows where the engine store lives. The work is deduplicated by index file, so repeated construction of a Runtime for the same workspace does not start another pass. `codegraph_explore`, `codegraph_node` and `codegraph_callers` wait for the index to finish before answering. If the build has not finished within `MIAO_CODEGRAPH_WAIT_MS` (120 seconds by default), the call returns an explicit "index still building" error instead of a partial answer. `codegraph_status` stays a bounded diagnostic so it can be used to watch progress.

## A worktree starts from its main checkout

A linked worktree is a separate directory, so it used to get a separate empty index and re-extract the whole repository. The first time a worktree is indexed, its index file is seeded from the main checkout's index, then refreshed against the worktree's files. Unchanged files keep their rows and only the files the branch changed are extracted. The worktree still owns its own index file; seeding never writes back into the main checkout's index.

## Answers say what they cover

Every codegraph answer now names the workspace it searched, and says that other checkouts are not indexed. A query that names a path outside the workspace gets an explicit warning, and a workspace with no indexed source files is called out instead of returning an empty symbol list. This makes the failure mode from a cross-repository question visible instead of looking like a complete answer from the wrong repository.
