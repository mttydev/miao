# miao v0.4.0

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.0.md)

v0.4.0 让 TUI 说操作者的语言，自动压缩运行全程可见、触发线提到窗口的 95%，`read_file` 遇到大文件不再报错。这也是 99 进位规则下的第一个版本：`0.3.99` 进位为 `0.4.0`。

## 界面说中文和英文

TUI 自己的界面文案现在跟随操作系统语言——侧栏的入/出/缓存列、会话用量与活动行、待办列表、工作区块、输入框的状态行与占位提示、Thinking 行——并新增 `/lang` 命令在 `en`、`zh` 之间切换或交还给系统locale（`auto`）。选择持久化在 `tui.json` 里；目录表保证每个标签的英文形态与迁移前逐字节一致，依赖英文断言的键盘习惯测试全部保持通过（#3236）。

## 自动压缩全程可见

超过 30 秒的压缩过程会把输入框旋转器转为警示色；完成的横幅以警示色加粗绘制（"context compacted · earlier turns summarized (N chars)"）；转录里新出现的压缩会在输入框通知一次——传输重连导致的快照重放保持安静（#3235）。

## 压缩触发线提到窗口的 95%

声明窗口的触发线原来在 88% 就位，重度使用的一天会以窗口三分之一的余量停手——操作者的日志显示会话峰值只到触发线的 99.3% 然后就再也没接近过。现在触发线在 95%：与 Codex 的有效上限一致、略低于 Claude Code 在 1M 窗口上的 ~96.7%，同时为摘要保留余量（#3233）。

## 大文件整体读取，以窗口形式

`read_file` 对 32 KiB–1 MiB 的源文件不再报错（"file is N bytes, above the 32768-byte whole-file bound"）——一个 635 行的 Python 文件就有 ~36 KB，以前每个中等大小的文件都要付一轮「报错+重试」。现在直接返回首个窗口，带 `truncated`/`total_lines` 元数据和说明边界的 note，`offset`/`limit` 从那里继续。上下文组装的探测保留原有的记录式跳过，超过 1 MiB 的读取仍然拒绝（#3234）。
