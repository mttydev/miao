# miao v0.3.91

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.3.91.md)

v0.3.91 堵上了「停下却不告诉操作者该做什么」的三条路径，让超长请求更便宜地装进窗口，并停止为没人看的诊断付出存储代价。

## 长期不更新的清单会被停下

此前的停滞守卫只衡量「重复的纯文本回复」，于是一条工具驱动的会话在 **176 个回合**里从未重写那份 14 项清单，而每个回合都只带着一句温和提醒。现在：清单仍有未完成项、且连续 12 个 provider 回合没有重写时，drain 会以 `loop.stopped{reason:"todo-stale"}` 停下，说明里点名 `todowrite`；到第 8 个回合，提醒本身升级为「在做任何进一步工具调用前先核对清单」的指令。已完成的清单、或没有清单的会话，永不被这样停下。

## 用尽的 Goal 预算会点名能解除它的命令

Goal 预算在第一个 provider 回合之前就中止 drain，而能重写它的工具恰恰需要那个回合——所以旧说明给出的动作在产品里并不存在。现在它点名 `/goal budget <turns>`：写入新的 Goal revision 并让已经在等待的输入继续。

## 超长请求先裁剪，再谈丢消息

当请求装不下时，运行器先按「保留最近一轮、单条 16KB」把旧工具输出省略，由旧到新，直到请求回到窗口预算之内；剩下的再交给整条消息裁剪。请求本来能装下的会话完全不受影响，因此缓存前缀保持稳定，持久记录也不丢任何字节。上下文长度导致的 400 也不再消耗那一次 self-heal 重放，因为溢出路径本身就会压缩并用受限请求重试。

## 更小的诊断，以及会自动重试平台取消的 CI

`cache_diagnostics` 为每条前缀消息存了 64 个字符的摘要——每条请求约 8.8KB、单个工作区账本约 470MB——只为比较相邻消息是否相同。现在只保留 16 个十六进制字符（64 bit），回答同一个问题。

同一天里，一个排队后**没有分配到 runner** 就被取消的 `macos-15` 作业三次挡住 CI 与发布。现在长生命周期分支上的 push run 若以「被取消」结束，会自动重跑，最多两次；PR 的 run 不在此列，因为新的推送取代旧 run 时的取消是预期行为。
