# miao v0.5.14

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.14.md)

v0.5.14 是一个修复版本：把套餐额度重新放回侧栏——只显示当前模型所用的账号，每个窗口一行，并且不再拖慢首次输入。

## 侧栏显示什么

`计划 · 配额` 现在会在首页与会话里显示当前模型对应账号的额度。每个窗口独占一行：进度条、百分比、套餐计价的已用/上限，以及重置倒计时。列宽不足时先省略金额、再省略倒计时，保证不换行。

- opencode-go：5 小时 / 周 / 月
- 智谱 / Z.ai coding plan：5 小时与周积分
- Command Code：5 小时与周窗口，以及月池

同一 provider 下的两个账号会分别显示（绑定账号时只显示当前账号），切换模型后额度块也随之切换到对应 provider。

## 之前为什么看不到

TUI 调用额度时带了一个 `{}` 参数，而引擎的 `Quota` 是 unit variant，请求在到达采集器之前就被拒绝——所以已发布版本里这个块从未画出来过。另一个问题让首次输入像在排队：采集器在命令循环里同步抓取四个 provider 端点，恰好同时到达的 Prompt 只能排在它们后面。

## 改了什么

- `quota` 与 `devices` 改为无参数调用。
- 额度立即返回缓存（冷缓存返回 `pending`），刷新放到后台任务；首条 Prompt 不再等待 provider 请求。
- 某个端点失败会先重试一次，仍失败则沿用该账号 15 分钟内的上次成功值。
- 额度行按当前模型的 provider 与 account 过滤，每个窗口只占一行。

## 验证

- 用构建出的 preview 做真实 PTY 运行：只显示当前 `opencode-go` 账号的 5 小时 / 周 / 月三行，数值与账号页面一致。
- `miao-tui` 863 个测试、`miao-engine` 650 个测试通过，两个 crate 的 clippy 均干净。
