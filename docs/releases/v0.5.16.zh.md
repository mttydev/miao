# miao v0.5.16

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.16.md)

v0.5.16 是一个修复版本：`miao -s <id>` 的启动时间大幅缩短。

## 之前慢在哪

存储索引记录每个会话在哪个 ledger 里，但每次启动都会先校验全部 523 个 ledger 的变更戳。正在写入的 ledger 总是比缓存晚一拍，于是校验失败、每次都要扫描所有数据库：`miao session find <id>` 要 1.31 秒，`-s` 在首帧前也要花同样的时间。

## 改了什么

缓存命中的会话现在只验证声明它的那一个 ledger：以只读方式打开，确认会话仍在，并读取它当前的 root（避免把 re-home 过的会话开到旧工作树）。任何不确定的情况——没有索引、版本不认识、没有候选、ledger 里已经没有这个会话——都回退到原来的扫描，所以缓存过期只会多花时间，不会给出错误结果。

同一台机器实测：`session find` 1.31 秒 → 0.01 秒，`-s` 的首个 alternate-screen 帧 1.16 秒 → 0.21 秒。

## 验证

- 三个新的 locate 测试：缓存之后 ledger 又变了、root 被 re-home、会话被删除后回退扫描。
- miao-cli `--bin miao`：73 个测试通过；clippy 无告警。
