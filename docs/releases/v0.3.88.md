# miao v0.3.88

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.88.zh.md)

v0.3.88 stops a turn from ending while the operator's goal is still open, and removes two labels and rows that said something other than what they measured.

## An active goal may not end on a text-only turn

A model that answers an approved instruction with a plan and no tool call has ended its drain: the engine sees a text-only turn, nothing continues it, and the operator re-prompts for each step they had already asked for once.

The run already refused to end while a configured `verification` command failed. That same boundary now reads the goal's durable record: while the goal is `active`, the first text-only turn admits one continuation that names the objective and states that "too large to do at once" is not a block; a second one records `loop.stopped` with reason `goal-open` and lets the run end visibly. The existing guards are untouched — a waiting list still idles, and a repeated no-progress turn still pauses.

## The sidebar says what it counts

The Activity row printed `interventions.*` — approvals, answers, rejections, cancels and edits accumulated over the whole Session — under the label `needs you`. That read as one pending question, with nothing anywhere to answer. It now says `decisions`.

## Fewer journal rows per turn

`instructions_loaded` was written on every provider turn, although readers only take the newest row to learn which sources are in force at a location: 47,299 such rows in one observed workspace. The row is now written only when `location` or `sources` actually changed, compared against the newest row inside the same transaction.
