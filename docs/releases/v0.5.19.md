# miao v0.5.19

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.19.zh.md)

v0.5.19 is a patch that removes the multi-second write at the end of every run on a large ledger.

## Finishing a run no longer scans the tool table

Every run finish asks for that run's planned or dispatched tools. `engine_tool` had only its primary-key index, so the query scanned the whole table. On the reported 3.5 GB ledger that is 95,829 rows and 64 MB of tool input: 3.25 seconds on a copy, and the bulk of the 10–16 second transactions that held up projections while seven windows shared the ledger.

`engine_tool` now carries a `(run_id, state)` index. The same query is a `SEARCH` and runs in 0.00 seconds on the copy; the interrupted-tools update in the same transaction uses it too.

## One-time index build

The index ships in the idempotent schema batch rather than a versioned migration. The first open of an existing ledger builds it once — about 3.4 seconds on the 3.5 GB copy — and every later open is a no-op. Upgrading therefore does not require closing every other miao window first.

## Verification

- `tool_index_tests`: 2 passed — the reconcile query plan uses the index, and a ledger whose index was dropped gets it back on the next open.
- miao-engine 653 lib tests; clippy clean.
- Copy of the reported ledger: 3.25 s full scan → 0.00 s index search.
