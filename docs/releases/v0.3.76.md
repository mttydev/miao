# miao v0.3.76

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.76.zh.md)

v0.3.76 kills the engine child process on TUI exit, so an engine daemon running an older binary can never silently undo the operator's update. The status strip folds into the composer's border, the recurring paste-image wedge and the `input id conflicts with an existing admission` failure are gone, invalid tool inputs name the field to drop, compaction is diagnosable from the store, and the desktop window streams assistant output, picks the Session's model, and speaks through the shared i18n layer.

## The engine dies when the TUI dies (#3072)

The TUI spawns miao-engine as a child process. When the TUI exits, the engine became an orphaned daemon that kept running the binary it was started with. When the operator updated miao and restarted the TUI, the TUI reconnected to the old engine daemon — which silently used the old arithmetic. Every fix the update carried was wasted.

The Connection now stores the spawned child process and kills it on Drop. The engine's lifecycle is the TUI's lifecycle: exit the TUI and the engine dies; restart the TUI and a fresh engine with the current binary is spawned.

## The status strip folds into the composer's border (#3067)

The status strip was a separate row below the input, costing a row of vertical space and reading as a second chrome band. The box already carried the run's phase, queue depth and notices on its title; the strip's facts now fold into the box's bottom border — state hints, the model in accent, turns and spend — with `miao <version>` at the right edge. The conversation keeps the row the strip spent, and an armed leader chord menu still takes the border row over while it waits.

## The desktop window streams and manages (#3059–#3063)

The desktop window now streams assistant output from the engine's progress frames (#3063), picks the Session's model from the header (#3061), routes its copy through the shared i18n layer (#3059), and presents the conversation as a chat product (#3062).

## The paste-image wedge is closed (#3069, #3074's neighbor)

Pasting a screenshot and hitting enter before the clipboard read finished held the prompt — and when the picture landed and the held prompt sent, the draft stayed on screen with its `[Image 1]` marker while the composer kept the bytes. It read as unsent, invited the same prompt a second time, and the next paste appended a second marker next to the first. A held prompt now empties the composer when it actually sends; a refusal still hands the draft back.

## The recurring "input id conflicts with an existing admission" is gone (#3074)

One run lives through several drain activations (waiting → a background notice → continue), and the engine's self-continuation inputs restarted their identity counters per activation while the store rows survived — so two activations raced on one id, and once a pause had cancelled the row, the other activation's re-admission failed the whole run with `input id conflicts with an existing admission`. Every internal continuation id now carries a per-attempt uuid, and an admission conflict names the id and the state it hit (`in_xxx exists as cancelled`) in the run journal instead of a bare message.

## Invalid tool inputs name the field (#3071)

A write that carried a field the schema never declared — `verified` rides every todo echo — answered a bare `invalid tool input`, and models resented the identical call for turn after turn. The rejection now names the field and where it sits: `invalid tool input: todowrite does not accept todos[0].verified`.

## Compaction is diagnosable from the store (#3065, #3068)

A summarizer pass now records `compaction.started` durably, and the stretches the circuit breaker spent open record `compaction.skipped` — so "why did this Session grow without compacting" is answerable from the per-workspace store without the engine's log. The usage-report scan also skips itself when the journal has not grown (#3068).

## IME composition no longer submits (#3064, #3066)

Typing Chinese and pressing Enter to confirm the composition submitted the message. Every textarea now tracks composition state and gates Enter/Escape on it.
