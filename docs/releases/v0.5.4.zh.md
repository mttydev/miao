# miao v0.5.4

v0.5.4 让对话区更好读，也让它不再声称已经不存在的事：你输入的消息一眼可辨，已完成的任务不再挂着名字，提供方会拒绝的图片会先被缩放再发送。工作区读取边界和第二个窗口的升级行为，也改成了提示里写的那个意思。

## 你输入的消息重新成为一块

过去你的话只是 `❯` 后面的一行，长对话里一条提问和周围的正文长得一样。现在每条输入都带一块主题面板色的底色：渲染层本来就会把带背景的行补到窗格右缘，所以底色在换行行上连续、一直铺到右列。它不加边框、不加空行，短问题仍然只占每行一行的空间。颜色来自主题；`NO_COLOR` 下整块底色都不画。

## 已完成的任务不再挂着自己的名字

输入框曾显示 `等待 1 个后台作业 · 37m 12s · <命令>`，而引擎早已把该任务标为完成；计时还在走，是因为它每帧都用缓存的开始时间现算。等待行完全由缓存的任务行绘制，且缓存没有年龄上限，所以一旦读取不再到达窗口，最后一条 `running` 结果就会一直挂着，看起来像任务还在跑。

现在任务行会记录引擎应答的时间，超过十个轮询周期的行会在绘制前被丢弃。屏幕上有 running 行时，也保证下一拍一定排一次读取，缓存行不可能比它最后一次读取活得更久。引擎的暂停仍会持续触发读取，所以真实等待的详情会在引擎恢复应答后回来；一直沉默的读取现在显示普通的暂停状态，而不是一个编造出来的计时。

这类等待还有两条会「活过任务本身」的路径，这次一起关掉了。任务所属的 runtime 已经不在时（最常见是同窗口内的引擎重启），它在日志里会永远停在 `running`：会话租约记的是那个仍然活着的 pid。现在回收规则改为——除非是**另一个**活进程持有，否则就回收，与会话回收的规则一致。另外，输入框把超过「调用方声明的上限 + 结算余量」的任务行当作已结束，丢掉进程的任务再也不能让计时走上一整天。

## `/model` 立即打开

模型选择框本身是本地的，但过去这条命令要等引擎第一次 `model_catalog` 回包才开始绘制。冷启动（库迁移、路由生成）会把这次往返拖到数秒，界面看起来就像卡住了。现在选择框立刻用窗口已有的模型打开——没有模型时显示「正在读取模型」一行——回包后原地回填同一个对话框；你按 Esc 关掉的选择框不会被重新打开。

## 图片先适配，再交给提供方

带多张内联图片的会话曾每一轮都因 `image_dimensions_too_large` 失败：历史里保存的是原始字节，重放就会再次触发同一个确定性 400。现在引擎会把"发送副本"适配到提供方的限制——长边最多 2000 px、约 512 KB，用 JPEG 质量阶梯，透明图先试 PNG。历史存储的字节不动，所以已经卡住的会话下一轮就能恢复；那个 400 也不再被当作可重试错误原样重放。无法测量或解码的图片会被一段简短说明替换，而不是照样发送。

## 读取边界告诉你要怎么做

`read_file`、`read_image` 仍然拒绝工作区外的路径，但拒绝信息现在会说明可达范围：把文件复制进来，或通过宿主授予的只读引用读取。`read_file` 的描述也提到了这个范围；`bash`、`run_command`、`start_job` 会提示：写在工作区外的文件读不回来——把文档转换到 `/tmp` 不再白费一轮去读它。

## 新窗口会等旧窗口

在旧 miao 进程仍占用存储时打开新窗口，过去会以"没有引擎"启动：schema 升级在存储被占用时拒绝运行，而这次拒绝被当成启动失败，让你先关掉旧窗口。现在引擎把这种拒绝当作等待：提示一次另一个 miao 窗口正在使用该工作区的存储，每两秒重试一次，旧窗口关闭后自行启动。

## 本次还包括

- 采纳宿主页面底色后，输入底色仍保持与主题的关系；`NO_COLOR` 下不会留下不可见的行尾填充。
- 工作区边界的提示也覆盖 `run_command` 与 `start_job`，描述与拒绝信息一致。
