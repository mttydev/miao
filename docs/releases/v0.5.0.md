# miao v0.5.0

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.0.zh.md)

v0.5.0 stops concurrent Sessions from sharing a mutable checkout. The engine now
gives one Session the main checkout and places every other Session in its own
detached git worktree, then enforces that boundary instead of asking a model to
notice it.

0.5.0 is a minor because the owner explicitly chose to bump the line for this
structural change. The default remains patch releases until the third component
reaches 99; a minor is not chosen from a change's size or structure.

## A checkout has one writer

A git checkout has one HEAD, one index and one working tree. Two Sessions in the
same directory could not both be right: a `checkout`, `cherry-pick` or `reset`
from one moved the branch under the other, and one Session's uncommitted work
could be overwritten by the other's command. Seeing a detached HEAD or a
conflict and stopping did not restore what had already been disturbed.

`engine_checkout_lease` now records the one Session that owns the checkout's
write slot. Placement runs under a lock, and the lease is durable, so two
Sessions started at the same moment cannot both take it. A Session archived or
deleted releases the slot; an upgraded database gives it to the oldest live
Session already working in the checkout.

## Every other Session gets its own worktree

The first Session keeps the checkout. A later Session is placed in
`.miao-worktrees/<session>` with `git worktree add --detach`, so it carries the
starting commit without claiming a branch. The main checkout's HEAD and status
are not touched by the placement. The directory is written to
`.git/info/exclude`, so it does not appear as untracked work in any repository;
no tracked `.gitignore` needs editing.

A resumed Session keeps its recorded root. If the checkout was taken while it
was closed, it is re-placed before its next turn. If its worktree was removed
outside miao, a fresh one is created instead of silently falling back to the
shared checkout. Workspaces that are not git repositories keep their previous
behavior.

## Isolation is enforced, not advised

A Session's tool clone now carries its own root, directory and main checkout.
File tools resolve paths against the worktree, bash starts there, and background
jobs inherit the same root. A write that resolves into the main checkout is
refused by the existing containment check.

Process tools also refuse a git command redirected at the checkout: `git -C
<checkout>`, `--git-dir`, `--work-tree`, `GIT_DIR`, `GIT_WORK_TREE`, and a `cd`
that climbs back into it. `git diff A..B` remains a revision range, not a path,
and keeps working. A Session that is already in a shared checkout can call the
new `worktree_enter` tool to move itself into its own worktree without moving
its storage; the checkout's lease is released at the same time.

## Upgrade notes

The engine schema moves from 26 to 27. Close any miao window still holding the
old storage before starting the new build; the migration refuses to run beside a
live writer. Existing Sessions are re-homed on resume when the checkout is
already owned by another Session.

Worktrees are not deleted automatically: they contain the Session's files, so
removal stays explicit (`miao worktree remove` / the `worktree_remove` tool,
which refuses while a Session still works there).
