# miao v0.4.4

[English](https://github.com/mttydev/miao/blob/main/docs/releases/v0.4.4.md)

v0.4.4 修掉了昨日合并状态行的一处真实泄漏，并让首次安装明确告诉你该做什么，而不是无声无息。

## 合并状态行不再堆叠

状态条的可点击范围在两次绘制之间从未清空——字段文档写着"每次绘制清空"，代码却没做；点击依然正常（因为命中的是第一个覆盖范围），所以它一直以无限增长的内存形式潜伏。合并状态行改变了这笔账：它把每个范围都上报给宿主，于是一个过夜开着的会话把同样两条事实重复上报了 240 帧——mtty 状态行上堆出 480 个段。现在两个 pane 都在绘制开始时清空命中区，双帧绘制测试把上报内容钉死在当前帧实际布局的范围内（#3262）。

## 首次安装会告诉你下一步

在没有 provider key 的裸安装上，`/model` 此前会把文本当作提示词发给一个还起不来的引擎；provider 选择器则无声等待一个永远不会来的目录。现在 chrome 命令（`/model`、`/theme`、`/sessions`、`/lang`……）在输入的地方就地执行；会话内命令（`/goal`、`/tag`、`/recall`）与未知的斜杠文本仍作为首条提示词开新会话。当模型选择器或 provider 列表背后没有引擎时，它会直接说出配置步骤——完整的 `miao auth login <provider> <key>` 命令——而不是什么都不显示（#3260）。

## 维护与验证

CI 覆盖 `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings` 与 TUI crate 的全量 `cargo test`；Rust stable 工具链已升至 1.100，全部 chrome 在新 lint 下干净通过。
