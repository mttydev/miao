# miao v0.5.18

[简体中文](https://github.com/mttydev/miao/blob/main/docs/releases/v0.5.18.zh.md)

v0.5.18 is a patch that delivers the prompt queued behind a turn the operator interrupts.

## Escape stops the run it showed

A large ledger can lag the screen: one reported Session's ledger took 10–16 seconds per write transaction, so the projection that retires a finished run arrived minutes late while the band kept painting the prompts typed during the stall.

The next Escape used to cancel whatever was running when the request landed. By then the interrupted turn was gone and a successor drain was already carrying the queued prompt, so Escape cancelled that one before the model saw it and the prompt looked undelivered.

Escape now names the run the screen showed. The engine accepts it only while that run is still active; a stale id is ignored, so the successor delivering the queued prompt survives. The journal records the origin as `operator`, while a take-back keeps its own `take_back` origin.

## The queue band follows the projection

A submitted prompt is echoed in the band until the engine has it. The echo was retired only by the `input.promoted` event; a projection that no longer listed the input as pending kept it, because absence from the pending list looked the same as an admission the snapshot had not seen yet. A late or missed event therefore left a prompt painted as queued after it was already in the transcript.

Each echo now records the sequence its admission landed at. When a snapshot's cursor covers that admission and the input is no longer pending, the echo retires with the projection, so a slow or resynced screen stops naming prompts that already went in.

## Verification

- `guarded_cancel`: a stale execution id cannot stop the successor; `operator` and `take_back` origins are recorded separately.
- miao-tui 867 lib tests, including Escape naming the on-screen run and a projection retiring a promoted echo.
- miao-engine 651 lib tests; clippy clean for both crates.
