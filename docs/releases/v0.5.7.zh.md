# miao v0.5.7

v0.5.7 是一个补丁版本，修复三个问题：Windows 上的侧栏分割线、退出时成片报错、以及任何窗口宽度下都难以阅读的 Markdown 表格。

## 侧栏分割线保住自己的列

转录区与侧栏之间的分割线原本用 `│`（U+2502）绘制。这个字符属于 East Asian Ambiguous：`unicode-width` 记 1 列，CJK 控制台却按 2 列渲染——而 Windows 下 miao 正跑在 ConPTY 里。控制台会把分割线存进它自己的单元格和侧栏的第一格；重绘那一行时分割线又被清掉，于是出现不完整的浅色断线，滚动时还会向侧栏偏移 1–3 列。

现在分割线是 ASCII `|`，在任何宽度表下都占 1 列，并且每一帧都会重新发送，终端丢掉的行会在下一帧自愈。此前的修复改的是分割线周围的字形和重绘策略，没有换掉这个本身宽度不定的字符。

## 退出不再误报会话损坏

每次退出都会为每个历史会话打印一行：

```
miao-engine: Session ... is unavailable (file IO failed: background task failed); leaving it at the engine root
```

启动时会重新注册每一条已记录的会话根目录，每次注册要跑一到两次 `git rev-parse`。在会话历史很长的工作区里，这个遍历在窗口打开后仍继续运行；关闭窗口会丢弃 tokio 运行时，阻塞池被取消，剩下的每一行就把取消误报成根目录不可用。

记录在主检出根目录的会话不需要注册：未注册的会话本来就会回退到该根目录。启动现在只恢复工作树放置——这是回退无法复现的信息；会话真正启动时由 `Runtime::initialize` 注册，被外部删掉的工作树仍会被重新安置。

## 表格按窗格宽度排版，并可查看完整行

表格原本每行预渲染成一条字符画，每列硬性封顶 40 列，随后被当作普通文本折行。单元格被从中间折断，网格失去列位，窗口再宽表格也仍然很窄。

现在列宽使用窗格真正拥有的宽度：放得下就用真实列宽，放不下就做水位收缩，每个被截断的单元格以 `…` 结尾，表头、分隔线和正文共用同一组列位。表格行不再经过正文折行器。

鼠标停在某一行时，浮层会显示整行完整内容，并按列名标注每个单元格；鼠标移开该行或窗口失焦时浮层消失。

## 验证

`crates/miao-tui` 的 `cargo test`（854 个库测试）与 `crates/miao-engine` 的 `cargo test`（640 个库测试，加上放置与启动测试套件），`cargo clippy --all-targets -- -D warnings` 与 `rustfmt --check` 均通过。新增测试在去掉修复后会失败：CJK 宽度表下宽度超过 1 列的分割线、被正文折行器折开的表格行、表格列范围之外的悬停命中、以及按会话逐个启动 git 的启动遍历。
